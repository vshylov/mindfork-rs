# Мультиязычность CLI и остаточных поверхностей — «весь текст в бандлы»

> **Статус: дизайн-план, развилки §4 подтверждены пользователем (2026-07-14).**
> Продолжение направления i18n: оси A (язык агента, Ярусы 1–3 — [docs/i18n.md](i18n.md))
> и B (язык интерфейса — [docs/history/i18n-ui.md](history/i18n-ui.md)) завершены.
> Постановка пользователя (2026-07-14): «чтобы в бандлы переводов можно было
> переместить **абсолютно весь** текст, который показывается пользователю, в том
> числе и выводимый с помощью `println!`/`eprintln!`/`bail!` в `main.rs`».
>
> **Решения пользователя (2026-07-14):** все развилки §4 — по рекомендациям, **с одной
> поправкой к развилке 3**: при **полной неопределённости** языка (нет ни `settings.json`,
> ни `defaults.json`, либо `defaults.json` битый) печатаем на **английском**, а не на
> русском референсе. То есть финальный фолбэк `cli_lang()` и печать ранней ошибки
> (до знания языка) — `Lang::En`. Итог принятых развилок: (1) собственный
> микро-парсер (вариант B); (2) источник языка `settings → defaults → **en**`;
> (3) полная неопределённость → **en**; (4) однострочный `{префикс}: {err:#}`;
> (5) скоуп хвоста движка — `managed.rs` + `shared/sandbox.rs`, обёртки HTTP — граница;
> (6) `clap` удаляется из зависимостей.

## 1. Мотивация и рамка

После завершения осей A+B вне бандлов остались тексты, которые человек видит **в
консоли** (CLI-подкоманды `backup`/`restore`/`import-lamellama`/`sandbox`/`locales`,
сообщение second-instance, ранние ошибки старта TUI) и **в хвостах ошибок**
(anyhow-цепочки, всплывающие и в CLI, и в статус-чип/ленту). Это ось B — тексты для
человека, язык — глобальный `config.interface.language`; механизм тот же
(`shared/i18n`, ключи в бандлах), новых крейтов не требуется.

Две архитектурные проблемы, которых не было у прежних поверхностей оси B:

1. **Курица и яйцо на старте.** Язык UI живёт в `settings.json`, дефолт — в
   `defaults.json`; ошибки чтения этих файлов надо печатать *до* того, как язык
   известен. Смягчение: вшитые бандлы доступны **без** `i18n::init` (LazyLock над
   `include_str!`) — локализованная печать возможна с первой строки `main`, вопрос
   только в выборе языка.
2. **Текст, который генерирует не наш код**: справка/ошибки `clap`, префикс
   `Error:` из std при `main() -> Result`, «Caused by:» из anyhow, строки
   `io::Error` от ОС. Их нельзя «переместить в бандл» — можно либо заменить
   собственным выводом, либо объявить границей.

## 2. Инвентаризация (что осталось вне бандлов)

| Категория | Где | Куда всплывает | Язык |
|---|---|---|---|
| CLI-сообщения (~25) | `main.rs`: `println!`/`eprintln!`/`bail!` в `run_backup`/`run_restore`/`run_import`/`run_locales`, second-instance, `acquire_cli_guard` | stdout/stderr | UI |
| Справка/ошибки парсера аргументов | `clap` derive: `about`, doc-комментарии подкоманд/аргументов; служебные «Usage:»/«Options:»/«Commands:»/«Print help»; сообщения ошибок парсинга (`error: unexpected argument…`), ошибка диапазона `-c` | stdout/stderr | UI |
| anyhow-цепочки CLI-фич (~60) | `features/backup.rs` (~23: «создание архива…», «архив повреждён…», «небезопасное имя записи…»), `features/sandbox_setup.rs` (~30, включая **прогресс-колбэк**: «Скачивание…», «Распаковка…», «Готово. Песочница установлена», «sha256 не совпал…»), `features/migration.rs` (~5, англ.) | stdout/stderr | UI |
| shared-низ (~10) | `shared/paths.rs` (битый `defaults.json`, «создание каталога данных…», англ. exe-контексты), `shared/instance.rs` (thiserror `Display`), `shared/logging.rs` (1), англ. контексты `main.rs` («opening storage», «building tokio runtime») | stderr (часть — **до** знания языка) | UI |
| Стандартная обвязка ошибок | `Error: …` (std `Termination` при `main() -> Result`) + многострочный «Caused by:» (anyhow `Debug`) | stderr | — |
| Хвост движка (~10) | `shared/api/managed.rs` (предполёт/probe: «файл модели не найден…», «сервер… завершился до готовности…», «не вышел в готовность за…») → **статус-чип** «нет связи: why»; `shared/sandbox.rs` («песочница занята…», «бинарь wasmer не найден», контексты запуска) → **результат `python_exec`** (читает модель, видит человек) и **warmup CLI** | статус-бар / лента / stdout | чип — UI; результат инструмента — **язык профиля** (ось A); warmup — UI |
| Обёртки HTTP-клиентов | `shared/api/{openai,anthropic,gemini}` — контексты вокруг сетевых ошибок; основное содержимое — тело ошибки сервера (непереводимо в принципе) | лента (`AppEvent::Error`) | UI |

Не инвентаризируются (границы, §7): panics/`debug_assert`, `tracing`-логи,
`build.rs`, строки `io::Error` от ОС, тела ошибок внешних серверов.

## 3. Архитектура решения

### 3.1 Язык CLI — `cli_lang()`

Порядок разрешения: `settings.json` → `interface.language` (человек уже выбрал язык
в приложении — CLI для того же человека) → `defaults.json` **если файл присутствует**
→ `default_language` (инсталлятор заполнил) → **`En`** (полная неопределённость:
свежий бинарь без конфигурации — международный дефолт). Никакого нового поля
конфига/маркера. Битый `settings.json` → шаг ниже (та же терпимость, что
`load_config().unwrap_or_default()`). Существование файла `defaults.json`/legacy
`location.json` различается явно — иначе serde-дефолт `default_language=Ru` никогда
не дал бы дойти до `En`-хвоста (`default_language=Ru` — это дефолт **ланга каркаса**
новых профилей, ось A, а не сигнал языка отображения).

### 3.2 Read-only «peek»-фаза до парсинга аргументов

Сейчас `Cli::parse()` — первая строка `main`, поэтому `--help` не трогает диск.
Чтобы справка была локализованной (и внешними локалями тоже), язык и реестр локалей
нужны **до** парсинга — но `--help` не должен начать создавать каталоги.

- `Paths::discover()` делится на `Paths::resolve()` (чистое вычисление: exe_dir →
  `Defaults::read` → `root_dir`, **без** `create_dir_all`) и `paths.ensure_dirs()`
  (создание корня + `locales/`); `discover()` = `resolve()+ensure_dirs()` для
  совместимости вызовов в тестах.
- Порядок `main`: `resolve()` → `cli_lang()` (чтение `settings.json` read-only) →
  `i18n::init(locales_dir)` (read-only скан) → **парсинг аргументов с
  локализованными текстами** → CLI-ветки / TUI-ветка (`ensure_dirs()` →
  `logging::init` → …).
- **Предупреждения загрузки внешних локалей** сейчас уходят в `tracing` — при раннем
  `init` подписчик ещё не установлен. `init` начинает **возвращать**
  `Vec<String>`-предупреждения; TUI-ветка логирует их после `logging::init`,
  ветки раннего выхода (`--help`) молча отбрасывают (best-effort, как и было).
- Сбой `resolve()` (битый `defaults.json` — единственный реалистичный случай):
  язык неизвестен → печать на **английском из вшитого бандла** (§4, развилка 3,
  поправка пользователя).

### 3.3 `main() -> ExitCode`: печать ошибок — своя

`fn main() -> std::process::ExitCode` + `fn real_main(...) -> anyhow::Result<()>`.
На `Err` main печатает сам: `eprintln!("{}: {err:#}", loc.t("cli.err.prefix"))`
(формат `{:#}` — однострочная цепочка «msg: cause: cause», уже используется в
`run_restore`) и возвращает код 1. Это убирает английские `Error:` (std) и
«Caused by:» (anyhow Debug). Чистый хелпер `cli_error_line(loc, &err) -> String` —
тестируем без запуска бинарника.

### 3.4 Ключи `cli.*` и автоматическое расширение сетки

Новый префикс: `cli.help.*` (справка парсера), `cli.err.*` (префикс/обвязка),
`cli.ctx.*` (контексты старта), `cli.guard.*` (second-instance + «закройте
приложение, прежде чем {action}»), `cli.backup.*`, `cli.restore.*`,
`cli.sandbox.*`, `cli.import.*`, `cli.locales.*`, `cli.paths.*`. Значения ru —
**байт-в-байт** текущие строки (существующие ассерты не меняются — приём всех
i18n-PR). Вся существующая сетка безопасности расширяется **автоматически**:
`bundle_prefixes()` выводится из бандла → гейты «ключ из кода есть в бандле»,
«нет мёртвых ключей», key/placeholder parity и `en_bundle_has_no_cyrillic`
покрывают `cli.*` без правки тестов; `export_bundle` включает новые ключи сам.

### 3.5 Доставка локали в глубину — два устоявшихся паттерна

Правило выбора (оба уже в кодовой базе):

- **Параметр `&'static Locale`** — для функций с параметризованными глубокими
  цепочками (прецедент Яруса 2c: `fs`/`python`/`calc` протянули `loc` в хелперы):
  `backup::create_backup(..., loc)`, `backup::restore_backup(..., loc)`,
  `sandbox_setup::setup(..., loc)` (прогресс-строки — через `loc.tf`, сигнатура
  колбэка `FnMut(&str)` не меняется), `migration::import_dir(dir, loc)`,
  `Defaults::read(exe_dir, loc)` / `Paths::resolve(loc)`, `logging::init(paths, loc)`.
- **Структурная ошибка, форматирует граница** — для enum из 2–3 исходов (прецедент
  `ApiKeyError { NoName, Missing }` из оси B): `instance::InstanceError` остаётся
  thiserror-структурой, но его `Display` перестаёт быть пользовательским текстом —
  `main`/`acquire_cli_guard` формируют сообщение из бандла по варианту.

### 3.6 Парсер аргументов — центральная развилка (§4, развилка 1)

**Вариант A — остаться на clap, локализовать его поверхность.**
clap 4 derive принимает выражения в атрибутах (`#[command(about = expr)]`,
`#[arg(help = expr)]` — вызовы билдера в рантайме), т.е. справка подкоманд/аргументов
может читаться из бандла. Заголовки: «Usage:» — свой `help_template`, секции — 
`next_help_heading`/`subcommand_help_heading`, `--help`/`--version` — свои `Arg` с
`ArgAction::Help/Version` вместо автогенерируемых. Цена: (а) derive-выражения не
принимают параметров → нужна **глобальная** `OnceLock`-локаль CLI (ровно то, за что
отвергли `rust-i18n`); (б) **сообщения ошибок парсинга остаются английскими** —
рендер внутри clap; можно написать свой рендерер по `err.kind()`+`err.context()`
(~100 строк, хрупко к апгрейдам clap, fallback всё равно английский); (в) ошибка
диапазона `value_parser!(i64).range(0..=9)` — английская.

**Вариант B — собственный микро-парсер (`features/cli.rs`, ~200–250 строк + тесты).**
Поверхность мала: 5 подкоманд, 6 опций, 3 позиционных. Эскиз:

```rust
pub enum CliCommand {
    Run,                                  // без подкоманды → TUI
    Backup { output: Option<PathBuf>, compression: i64 },
    Restore { archive: PathBuf },
    ImportLamellama { dir: PathBuf },
    SandboxSetup { force: bool },
    LocalesExport { code: String, output: PathBuf },
    Help(Option<&'static str>),           // общая / по подкоманде
    Version,
}
pub fn parse(args: &[String], loc: &Locale) -> Result<CliCommand, String>; // Err — готовый текст
pub fn render_help(topic: Option<&str>, loc: &Locale) -> String;
```

Паритет форм с clap (покрыт тестами): `--opt value`, `--opt=value`, `-o value`,
`-h`/`--help` (глобально и после подкоманды), `-V`/`--version`; валидация `-c 0..=9`
и «файл уже существует» — свои тексты из бандла. **100 % текста из бандла**, локаль —
обычным параметром (без глобалов), минус зависимость (clap используется **только**
в `main.rs` — уходит целиком вместе с деревом clap_builder/anstream). Прецеденты
«крейт мешает требованию → своё микро-решение»: markdown (ADR 0003), i18n, calc,
InputBox (ADR 0001). Цена: переписывание работающего интерфейса; «did you mean»-
подсказок clap не будет (можно добавить простейшую по префиксу — не обязательно).

**Не переводится в обоих вариантах**: имена подкоманд и флагов (`backup`,
`--output`) — это протокол, как id инструментов и команды `/rag` (i18n.md §2.3).

### 3.7 Хвост движка: managed-probe и песочница

- `shared/api/managed.rs`: тексты предполёта/probe показываются в статус-чипе
  («нет связи: why») — это UI. `ManagedConfig` дополняется `loc: &'static Locale`
  (супервайзер уже получает локаль UI с оси B: `apply_chat(..., loc)`), ошибки —
  через ключи `ui.err.managed.*`. Закрывает давний «остаток» оси B.
- `shared/sandbox.rs`: двойная аудитория — ошибки уходят и в результат
  `python_exec` (язык **профиля**, ось A), и в warmup CLI (язык UI). Трейт
  `SandboxRunner::run` получает `loc` параметром (вызывающий выбирает: инструмент —
  `ctx.loc`, warmup — язык UI); ключи `sandbox.err.*`.
- Обёртки HTTP-клиентов (`shared/api/{openai,anthropic,gemini}`) — **граница** (по
  умолчанию, развилка 5): их основное содержимое — тело ошибки сервера/ОС,
  непереводимое в принципе; локализация трёх-четырёх слов обвязки не окупает
  протяжку локали во все клиенты и их тесты.

## 4. Развилки (подтвердить до реализации)

1. **Парсер CLI.** (A) clap + локализация поверхности, ошибки парсинга — граница
   (или свой рендерер по `ErrorKind`, всё равно не 100 %); (B) собственный
   микро-парсер — 100 % текста из бандла, локаль параметром, минус зависимость.
   **Рекомендация: B** — единственный честный путь к «абсолютно весь текст»;
   поверхность мала, прецеденты в ДНК проекта. A — если важнее нулевой churn
   рабочего CLI.
2. **Источник языка CLI.** ✅ `settings → defaults → **en**` (рекомендация +
   поправка пользователя: финальный фолбэк en, не ru). Env-override
   (`MINDFORK_UI_LANG`) не вводим — нет запроса.
3. **Ошибки до знания языка** (битый `defaults.json`). ✅ Печать на **английском** из
   вшитого бандла (поправка пользователя: полная неопределённость → en). Ключи те же,
   хардкода нет.
4. **Форма вывода ошибки.** Однострочная цепочка `{префикс}: {err:#}`
   (**рекомендация**, уже используется в restore); либо многострочный рендер с
   локализованным «Причина:».
5. **Скоуп хвоста движка.** Этап 3 = `managed.rs` (статус-чип) + `shared/sandbox.rs`
   (**рекомендация**); обёртки HTTP-клиентов остаются документированной границей.
   Альтернатива — протяжка локали во все клиенты (много churn, малый выигрыш).
6. **Судьба clap-зависимости при B.** Удалить из `Cargo.toml` (**рекомендация**)
   либо оставить на будущее (мёртвый груз — против конвенций).

## 6. Тесты

- **Автоматически**: все четыре гейта бандлов + parity + no-cyrillic накрывают
  `cli.*` без правок (§3.4).
- **Новые юниты**: порядок `cli_lang` (tempdir: settings > defaults > ru; битый
  settings → шаг ниже); `Paths::resolve` не создаёт каталогов / `ensure_dirs`
  создаёт; `cli_error_line` (локализованный префикс, формат `{:#}`); при B — таблица
  разбора парсера (все подкоманды/формы опций/ошибки/`-c` вне диапазона/`--help`
  после подкоманды), `render_help` не содержит неподставленных `{…}` по всем
  `Lang::ALL`.
- **ru байт-в-байт**: существующие тесты backup/sandbox_setup/migration/paths не
  меняют ассертов — call sites получают `ru()`-локаль (приём всех i18n-PR).
- **Живой прогон не требуется** (движок не затронут — как ось B); ручная проверка
  реального бинарника: `--help`/ошибка парсинга/`backup` на ru и en
  (`settings.json`), внешняя локаль `de` + `interface.language=de` → CLI на de,
  битый `defaults.json` → ru-фолбэк.

## 7. Границы (осознанно НЕ локализуется)

- **Строки `io::Error`** — их формирует ОС (на Windows уже на языке ОС) и тела
  ошибок внешних серверов (HTTP) — приходят готовым текстом.
- **Обёртки HTTP-клиентов** (при развилке 5 = рекомендация) — см. §3.7.
- **panics / `debug_assert` / `unreachable!`** — для разработчика, не пользователя.
- **`tracing`-логи** — конвенция «только в файл, на русском» (i18n.md §2.3).
- **Имена подкоманд/флагов CLI** — протокол (§3.6).
- **Сообщения ошибок clap** — только если выбрана развилка 1A.

## 8. Вне объёма

- Локализация/алиасы имён команд (`backup` → `бэкап`) — как алиасы `/rag`, задел.
- Определение языка по системной локали ОС.
- Перевод существующих данных пользователя.
