## Исходная точка (что есть сейчас)

- **Форматы:** `features/rag_ingest.rs::SUPPORTED_EXTENSIONS = ["txt","md"]`;
  `is_supported` по расширению; `read_text` — plain UTF-8 (отбрасывает BOM).
- **Индексация:** `app/orchestrator/rag.rs::index_source` уже ветвит md/txt
  (`chunk_markdown` по заголовкам vs `chunk_text`); чанкинг → эмбеддинг батчем →
  запись в sqlite-vec, изоляция по `profile_id`.
- **Прогресс:** `RagProgress::Indexing { index, total, name, dir }` — гранулярность
  **по файлу** (эмбеддинг файла идёт одним батчем).
- **Извлечение при поиске:** `features/tools/rag.rs::RagSearch` → `stitch_hits`
  склеивает соседние чанки **внутри источника** по дословному перекрытию
  (`MIN_STITCH_OVERLAP=24`); межисточниковой дедупликации/ранкинга **нет** (порядок —
  по `distance`).
- **Опорный паттерн реранкинга:** `features/tools/web.rs::rerank_by_embeddings` /
  `rerank_order` (эмбеддинг запроса + результатов, сортировка по косинусу, стабильная
  при равенстве, мягкая деградация без эмбеддера).

## Принципы (в духе проекта)

- **«Лучшее усилие»** — сбой извлечения одного источника логируется и не валит
  индексацию (как enrichment web); реранкинг без эмбеддера пропускается.
- **Изоляция по `profile_id`** — во всех запросах (инвариант).
- **Проверка лицензий новых зависимостей** — через `deny.toml` (как mermaid-крейты).
- **Разбиение по риску зависимостей** — форматы без новых крейтов отдельным PR от
  форматов с крейтами.

## Этап B1 — новые форматы источников

Ввести диспетчер извлечения текста по расширению вместо прямого `read_text`. Разбить
на два PR по зависимостям.

### Шаг B1a — HTML (без новых зависимостей)

- Переиспользовать `web::extract_readable` (scraper; уже `pub(crate)`) — читаемый
  текст из `<article>`/`<main>`, отбрасывая nav/header/footer/aside.
- `SUPPORTED_EXTENSIONS` += `html`/`htm`; `read_text` → `extract_text(path)` с
  диспетчером (txt/md → как есть; html → `extract_readable`).
- `index_source` (`orchestrator/rag.rs`) уже ветвит по расширению — добавить ветку.
- **Чистый выигрыш, низкий риск.** Тесты: извлечение читаемого текста из HTML-фикстуры
  на tempdir (nav/скрипты отброшены).

### Шаг B1b — PDF/DOCX (новые зависимости)

- **PDF:** крейт `pdf-extract`/`lopdf` — извлечение текста; качество варьируется
  (усечение/мусор допустимы — «лучшее усилие», логировать).
- **DOCX:** `docx-rs` или zip+xml-разбор (`document.xml`).
- `extract_text` расширяется ветками; извлечённое → `chunk_text` (структуры
  заголовков у pdf/docx нет).
- **`Cargo.toml`/`deny.toml`** — новые крейты + лицензии в allowlist. Тесты: фикстуры
  каждого формата на tempdir; сетевого/живого прогона не требуется.

**Риск:** средний (качество извлечения PDF); смягчается «лучшим усилием» + логами.

## Этап B2 — ранкинг/дедуп между источниками + прогресс по чанкам

### Шаг B2a — прогресс индексации по чанкам

- Сейчас `RagProgress::Indexing` — по файлу. Добавить гранулярность «чанк i/N внутри
  файла» (поле `chunk`/`chunk_total` в `Indexing` либо отдельный вариант).
- `spawn_rag_ingest`/`index_source` эмитят прогресс между чанками (эмбеддинг сейчас
  один батч на файл — либо разбить на под-батчи, либо эмитить после записи каждого
  чанка).
- `screens/chat/rag.rs` — баннер показывает чанк-прогресс. Низкий риск, UI-плюмбинга.

### Шаг B2b — кросс-источниковый дедуп/ранкинг в `rag_search`

- Поверх `stitch_hits` (внутри источника) добавить отсев near-duplicate пассажей из
  **разных** источников по косинусу + опциональный реранкинг по запросу
  (переиспользовать паттерн `rerank_by_embeddings`/`rerank_order` из web.rs).
- **Мягкая деградация** без эмбеддера — остаётся порядок по `distance` (как реранкинг
  web/RAG).
- Тесты: near-duplicate из двух источников схлопывается; при равенстве стабильно; без
  эмбеддера — прежний порядок.

**Оценка:** B2a — быстро и полезно; B2b — улучшение качества поиска (roadmap ставит
его последним пунктом раздела).
