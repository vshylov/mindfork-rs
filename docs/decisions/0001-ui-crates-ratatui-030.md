# ADR 0001 — UI-крейты под ratatui 0.30 (textarea, markdown, scroll)

**Статус:** принято (2026-06-14); markdown-часть уточнена
[ADR 0003](0003-own-markdown-renderer.md) (пост-M9: `tui-markdown` заменён
собственным рендерером ради таблиц/math/темы). Закрывает `[R]` «UI-крейты» из
[plan.md §M3](../../plan.md).
**Контекст:** проект зафиксирован на `ratatui 0.30.1`. spec §11.4–11.5 предлагает
`tui-textarea` (ввод) и `ratatui-markdown` (рендер markdown), с fallback на
`tui-markdown`. Нужно проверить совместимость с фактической версией ratatui.

## Факты (проверено эмпирически: `cargo add` + `cargo tree` + `cargo check`)

ratatui 0.30 выделил ядро в крейт `ratatui-core 0.1`. Крейты экосистемы делятся на
тех, кто перешёл на `ratatui-core ^0.1` (совместимы с 0.30), и тех, кто всё ещё
держит `ratatui ^0.29` (несовместимы — тянут вторую копию ratatui).

| Крейт | Версия | Зависимость | Вердикт |
|---|---|---|---|
| `tui-textarea` | 0.7.0 (10.2024) | `ratatui ^0.29` | ❌ устарел, лочит 0.29 |
| `ratatui-textarea` | — | — | ❌ не существует на crates.io |
| `ratatui-markdown` | 0.3.6 | `ratatui ^0.29` | ❌ лочит 0.29 |
| **`tui-markdown`** | 0.3.7 (12.2025) | `ratatui-core ^0.1` | ✅ собирается с 0.30.1 |
| **`tui-scrollview`** | 0.6.5 | `ratatui-core ^0.1` | ✅ собирается с 0.30.1 |
| `edtui` | 0.11.3 (04.2026) | `ratatui-core ^0.1` | ✅ собирается, но модальный (vim) |

Все совместимые кандидаты унифицируются на единственной `ratatui-core 0.1.1`
(нет дублей ratatui), `cargo check` зелёный.

## Решение

1. **Markdown → `tui-markdown` 0.3.7** (вместо `ratatui-markdown`, лочащего 0.29).
   Поддерживает по сути всё нужное: markdown → `ratatui::text::Text`, подсветка
   кода (syntect). Используется в `shared/markdown.rs`; поверх — наша
   unicode-аппроксимация LaTeX и сворачиваемые CoT/tool-блоки (наш код, spec §11.4).
2. **Скролл ленты → `tui-scrollview` 0.6.5**.
3. **Ввод → собственный минимальный multiline-виджет** (`widgets/input_box.rs`),
   НЕ внешний крейт. Обоснование:
   - `tui-textarea`/`ratatui-textarea` недоступны под 0.30 (см. таблицу).
   - `edtui` совместим, но модальная (vim) модель не соответствует UX простого
     поля чата и тянет лишние зависимости (clipboard/image/x11rb).
   - `tui-textarea` **в принципе** не имеет API диагностик/подчёркиваний
     произвольных диапазонов — это отдельный открытый `[R]` спелл-чека (spec §11.5).
     Свой виджет закрывает оба вопроса разом: полный контроль над `Shift+Enter`
     vs `Enter`, скроллом и над подсветкой слов с ошибками (per-span стиль).
   - Цена — ~250 строк хорошо тестируемого кода без новых зависимостей.

## Следствия

- Раздел spec §11.4–11.5 уточняется этим ADR: `ratatui-markdown`→`tui-markdown`,
  `tui-textarea`→собственный виджет.
- Открытый `[R]` «Отрисовка спелл-чека в textarea» (spec §11.5) **снят**: рисуем
  сами per-span стилем `UNDERLINED` поверх собственного виджета ввода.
- Пересмотреть при выходе обновления `tui-textarea`/`ratatui-markdown` под 0.30
  (если появится богаче нашего — миграция не обязательна, наш виджет самодостаточен).
