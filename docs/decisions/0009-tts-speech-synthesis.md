# ADR 0009 — Озвучивание сообщений (TTS): облачный провайдер + свой речевой экстрактор + плеер в процессе

**Статус:** принято (2026-07-23). Независимый «серверный слот», как эмбеддинги
([ADR 0002](0002-embeddings-dedicated-server.md)); ключи облаков — общие с чатом
([ADR 0008](0008-api-key-storage.md)); речевой экстрактор — второй потребитель
событий нашего markdown-рендерера ([ADR 0003](0003-own-markdown-renderer.md)).
Исследование, спайк и развилки Р1–Р9 — [docs/research/tts.md](../research/tts.md)
(решение 2026-07-23, §13).

**Контекст.** Направление озвучивания чата было один раз реализовано и **откачено**:
ни один тогдашний движок не дал приемлемого качества (OpenAI монотонно, piper «без
поставленной речи», Gemini — «франкенштейн» из-за дрейфа голоса между чанками + `503`).
Пере-исследование живым спайком (6 локальных + 3 облачных кандидата на реальном железе,
качество — на слух пользователя, дрейф — объективно по разбросу F0) показало: локальные
движки либо NO-GO по русскому (неверные ударения, китайский акцент), либо требуют своего
Rust-фронтенда (vosk-tts), а **OpenAI TTS звучит отлично** (ударения ~1 ошибка на абзац,
англицизмы нативно, дрейфа нет). Ключевой продуктовый довод — OpenAI это **не новый
vendor**: ключ уже хранится (ADR 0008), пользователю ничего не регистрировать.

## Решение

### 1. Основной путь — облако, локальный движок — задел

Порядок из исходного плана (Р1: «локальный первичен») **отменён**. Основной режим —
**OpenAI TTS** (`gpt-4o-mini-tts`, голос по умолчанию `onyx` — единственный отслушанный
в спайке); объём — **OpenAI + Gemini + external** (три варианта `TtsMode`). **Локального
сайдкара нет.** Локальный движок (vosk-tts + свой русский фронтенд ударений на BERT,
`mindfork tts setup` по образцу [ADR 0005](0005-python-sandbox-wasmer.md)) — задел для
offline/не-OpenAI аудитории; ElevenLabs/Azure не берём (требуют своей регистрации, что
противоречит доводу «не новый vendor»). Managed-режим в селектор не добавлен, пока нет
реализации (прецедент `Claude` до `AnthropicClient` — нерабочий пункт не шипим).

Отклонено (§13 исследования, с замерами): **Qwen3-TTS** (китайский акцент на англицизмах,
дрейф при нарезке, неверные ударения), **Supertonic 3** (ударения не чинятся даже
разметкой; OpenRAIL-M-веса), **vosk-tts** (Apache-2.0 и ударения по контексту, но 22 кГц
и своя Rust-подсистема фронтенда) — оставлен главным кандидатом задела.

### 2. TTS — независимый «серверный слот»

У Anthropic TTS нет вовсе, поэтому провайдер озвучивания конфигурируется **отдельно от
chat-движка** — как выделенный embedding-сервер (ADR 0002). Пользователь Claude
озвучивает через OpenAI/Gemini/external. Клиенты **stateless**: строятся из снимка
конфига на вызов (`engines_from_config`), менеджер-слот не нужен. Ключ облака берётся из
общих записей `api_keys` по провайдеру (ADR 0008) — вводить заново не нужно; фолбэк на
env-переменную сохранён. Конфиг `TtsSettings` — всё `#[serde(default)]`, без миграций.

### 3. Один OpenAI-клиент на облако и external; Gemini — свой транспорт

`OpenAiTts` обслуживает **и** облако OpenAI (формат `pcm` — сырой s16le 24 кГц mono,
мимо декодера), **и** любой сторонний OpenAI-совместимый сервер (формат `wav` — самый
переносимый, через декодер) — различаются base URL/ключом/форматом ответа. Gemini —
нативный `generateContent` c `responseModalities:["AUDIO"]` (тот же транспорт, что
`GeminiClient`), PCM из `inlineData`; **обязательная директива чтения** (дефолт
`Read this text aloud verbatim`) против ошибки `400 Model tried to generate text`.
Известные минусы Gemini (503-перегрузка, дрейф голоса между чанками) — причина, почему
он опция, а не дефолт.

### 4. Речевой экстрактор — второй walker по событиям `pulldown-cmark`

Поскольку рендерер ленты уже свой (ADR 0003), «речевой» экстрактор
(`shared/markdown/speak.rs::speakable_text`) — ещё один потребитель тех же событий, а не
отдельный парсер. Блоки кода, ` ```mermaid `, таблицы, display-math **пропускаются с
короткой голосовой пометкой** («блок кода пропущен») на **языке профиля** (ось A i18n —
это речевой контент, а не UI-хром); inline-код читается текстом, inline-math →
`latex_to_unicode`, ссылки → текст. «Мысли» (CoT) и tool-блоки не озвучиваются вовсе
(их нет в `Message.text`). Экстрактор — чистая функция, покрыт golden-тестами без движка.

### 5. Воспроизведение — `rodio` в процессе приложения

Плеер в процессе (`shared/tts/playback.rs`), не сайдкар-плеер: на Windows нет пригодного
встроенного CLI-плеера, а `Player::append` даёт очередь → **конвейер** «синтез чанка N+1,
пока играет N» бесплатно, с мгновенной отменой. Устройство открывается **лениво** (по
команде `/tts`, не на старте — libasound шумит в stderr при энумерации, cpal#384) и
**в обработчике** (не в задаче), оборачивается в `Arc<Playback>` (`Send+Sync`) и делится
с фоновой задачей — чтобы `/tts pause`/`resume` (на `rodio::Player::pause`/`play`)
применялись мгновенно. Нет звуковой карты (headless/CI) → `open` возвращает `Err`, а не
паникует: мягкая деградация «звук недоступен» (паттерн `UnavailableEmbedder`, ADR 0002).

### 6. Оркестрация: снимок + чанкинг до лимита провайдера + роль в пайплайне

Устроено по образцу RAG-команд: `/tts` → снимок переписки у оркестратора (единственный
владелец `Chat`) → отменяемая фоновая задача; генерация **не гейтится** (озвучивается
снимок). Точки остановки в одном хелпере (`stop_tts`): по настройке (смена чата, старт
генерации) и безусловно (удаление обмена `Ctrl+E`, перегенерация `Ctrl+R`, удаление чата).
Текст режется по предложениям и **пакуется до лимита провайдера** (OpenAI 4096, Gemini/
external 2000): типичное сообщение уходит **одним запросом** — «выросших пауз» из
пофразовой нарезки нет. Пайплайн **несёт роль** (`Vec<(MessageRole, String)>`): при
заданном отдельном «Голосе пользователя» (`user_voice`), отличном от голоса ассистента,
строится **второй движок** — реплики пользователя читаются им (`/tts all`). Голос —
свойство клиента при создании, поэтому два инстанса, а не параметр `synthesize` (минимум
правок трейта); при пустом `user_voice` — один голос.

### 7. Восстановление из отревертнутого этапа, а не переписывание

Реализация поднята из отревертнутого этапа 1 (`git show 19ead9f`): `main` по коду был
**тождественен** базе TTS (реверты чисто отменили фичу, а сама она росла поверх
API-ключей), поэтому восстановление свелось к чистому возврату файлов — код проверенный
(проходил тесты + живой прогон до реверта), собрался и прошёл гейты без правок.

## Последствия

- **Плюс:** качество основного пути подтверждено живым спайком и слухом пользователя (в
  т.ч. на сложном философском тексте). Три причины провала первого захода закрыты:
  OpenAI-монотонность была ошибкой конфигурации (голос/модель/отсутствие `instructions`);
  «выросшие паузы» — артефакт пофразовой нарезки, снят упаковкой до лимита (одно
  сообщение = один запрос); Gemini-дрейф остаётся его свойством, поэтому он опция, а
  дефолт — OpenAI, у которого дрейфа нет.
- **Плюс:** не новый vendor для пользователя (ключ OpenAI уже есть, ADR 0008); TTS
  дешевле LLM.
- **Плюс:** речевой экстрактор и плеер переиспользуют существующее (рендерер ADR 0003,
  паттерн мягкой деградации ADR 0002); конфиг без миграций.
- **Минус:** новая **системная** C-зависимость — ALSA на Linux (сборка `libasound2-dev`,
  рантайм `libasound2t64`/`alsa-lib`; Windows — чистый windows-rs), + MPL-2.0 (Symphonia)
  в `deny.toml`. Linux-путь и пакеты проверяются CI, не разработкой на Windows.
- **Минус:** OpenAI TTS требует ключа OpenAI — у пользователя чата на Claude/Gemini/
  локальной модели его может не быть; TTS опционален, для offline остаётся `external`.
- **Задел:** локальный движок (vosk + свой Rust-фронтенд ударений, `mindfork tts setup`);
  склейка чанков через границы речевых блоков (ещё более гладкая многоабзацная озвучка);
  SSE-стриминг внутри чанка; кэш аудио; нативный мульти-спикер Gemini (один запрос,
  несколько голосов); озвучка выбранного сообщения из ленты; ОС-TTS.
