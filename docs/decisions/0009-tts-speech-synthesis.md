# ADR 0009. Озвучивание сообщений (TTS): провайдеры, воспроизведение, границы

- **Статус:** принято (2026-07-21)
- **Контекст:** направление «озвучивание сообщений чата», исследование
  [docs/research/tts.md](../research/tts.md) (развилки Р1–Р9 приняты пользователем
  2026-07-21), этап 1 `feat/tts-core` + этап 2 `feat/tts-sidecar`
- **Связано:** ADR 0002 (выделенный сервер как паттерн независимого слота),
  ADR 0003 (свой markdown-рендерер — речевой экстрактор поверх тех же событий),
  ADR 0004 (контракт движка и мульти-провайдерный инференс),
  ADR 0005 (сайдкар + провизия ассетов по lock-списку), ADR 0008 (хранение API-ключей)

## Решение

### 1. Озвучивание — независимый «серверный слот», а не свойство chat-движка

У Anthropic озвучивания **нет вовсе** (проверено по всей поверхности API), поэтому
привязать TTS к выбранному провайдеру чата нельзя: пользователь Claude остался бы
без озвучки. Провайдер синтеза конфигурируется отдельно (`AppConfig.tts`, вкладка
«Озвучивание» секции «Модель») — ровно как выделенный embedding-сервер (ADR 0002).
API-ключ облака при этом **общий** с чатом (ADR 0008): вводить его заново не нужно.

Контракт — `shared::tts::TtsEngine { synthesize(text, cancel) -> AudioClip;
max_input_chars() }`; реализации подключаются как новые режимы `TtsMode`, слои выше
(команда, оркестрация, воспроизведение) не меняются:

| Режим | Реализация |
|---|---|
| `managed` | локальный сайдкар `piper` (`shared::tts::sidecar`) — §2 |
| `openai` | `POST /v1/audio/speech`, ответ `pcm` (24 кГц s16le) |
| `gemini` | нативный `generateContent` + `responseModalities:["AUDIO"]` |
| `external` | тот же клиент, что у OpenAI, но чужой base URL и ответ `wav` |

### 2. Локальный движок — сайдкар `piper` (а не CLI sherpa-onnx и не in-process крейт)

Исследование рекомендовало рантайм **sherpa-onnx** в подварианте «(а) CLI-сайдкар».
Спайк этапа 2 этот подвариант **закрыл**: `sherpa-onnx-offline-tts` принимает текст
только позиционным аргументом, а его узкий `main()` заставляет Windows-CRT
конвертировать argv из UTF-16 в ANSI-кодовую страницу (у типичной русской установки
`1252`) — **вся кириллица превращается в `?` и синтезируется тишина**. Внешний
манифест с `activeCodePage=UTF-8` игнорируется, опции «текст из файла/stdin» у CLI
нет. Для русскоязычного приложения это блокер.

Выбран подвариант **(в) — MIT-бинарь `piper` 2023.11.14-2**: текст идёт **через
stdin** (UTF-8 байтами, конвертации нет), сырой PCM возвращается в stdout
(`--output_raw`) — временный файл не нужен. Отклонённая альтернатива (б),
официальный Rust-крейт in-process, дала бы однократную загрузку модели и покадровый
стриминг, но потребовала бы статической линковки C++/onnxruntime в наш бинарь,
сетевого шага build-script и правок CI/пакетирования — против духа проекта
(прецедент wasmer, ADR 0005) и несоразмерно выигрышу.

**Принятые цены варианта:**

- апстрим piper заархивирован (10.2025) — багфиксов не будет; версия пришпилена в
  lock-списке, поведение зафиксировано тестами;
- модель грузится **на каждый спавн** (~0.8 с, замерено): смягчено крупным
  `max_input_chars` (2000 символов — чанкер складывает больше предложений в вызов);
- голоса нужны **оригинальные** с HuggingFace: переэкспортированные ONNX из model
  zoo sherpa роняют бинарь (проверено);
- латинские вставки в русском голосе читаются с акцентом (дефект espeak-фронтенда) —
  маршрутизация по алфавиту двумя голосами остаётся заделом.

### 3. Голоса — только permissive-лицензии

В набор `tts setup` входят `ru_RU-dmitri-medium` (по умолчанию) и
`ru_RU-denis-medium` (по `--voice`) — данные **CC0** — и английский
`en_US-amy-medium`. **Не берём:** `ru_RU-ruslan` (CC BY-NC-SA), `ru_RU-irina`
(«License: Unknown»), Silero (CC BY-NC-SA), XTTS-v2 (CPML) — некоммерческие
лицензии несовместимы с проектом. Supertonic 3 (MIT-код, OpenRAIL-M-веса) отслушан
в спайке и оставлен заделом.

### 4. Провизия — `mindfork tts setup` по lock-списку URL + sha256

Калька с ADR 0005: бинарь и голоса скачиваются в `data/tts/` с проверкой sha256,
идемпотентно, `--force` перекачивает. Общая механика (скачивание потоком/в память,
сверка хэша, распаковка tar.gz/zip) вынесена в `features::provision` — её делят обе
setup-команды. Раскладка (`data/tts/piper/piper[.exe]`, `data/tts/voices/*.onnx`)
известна и рантайму, и провизии через общий резолвер `sidecar::locate_piper`.

Автоустановки при первом `/tts` **нет**: скачивание ~130 МБ — явное действие
пользователя (та же логика, что у песочницы Python).

### 5. Воспроизведение — `rodio` в процессе, не сайдкар-плеер

`Player::append()` даёт очередь источников, поэтому конвейер «синтезируем чанк N+1,
пока играет N» получается штатно, а отмена мгновенна (`clear`/`stop`). Сайдкар-плеер
отклонён: на Windows нет пригодного встроенного CLI-плеера, а стыки чанков и отмена
были бы хуже по построению.

Принятая цена — единственная новая **системная** зависимость проекта: ALSA на Linux
(`libasound2-dev` в CI, `libasound2t64 | libasound2` / `alsa-lib` в пакетах) и
MPL-2.0 (Symphonia) в `deny.toml`. Две ловушки TUI зафиксированы в коде:
`log_on_drop(false)` (иначе rodio пишет в stderr поверх интерфейса) и ленивое
открытие устройства (libasound шумит в stderr при энумерации, cpal#384). Нет
звуковой карты → заметка «звук недоступен», а не паника (паттерн
`UnavailableEmbedder`).

## Границы (осознанно вне объёма)

- **ОС-TTS без моделей** (WinRT «Microsoft Irina», speech-dispatcher) — качество
  legacy, на Linux болото зависимостей (Р9).
- **`llama-server` для TTS** — эндпоинта `/v1/audio/speech` у него нет; вернуться,
  если появится.
- **SSE-стриминг внутри чанка**, кэш аудио, авто-выбор голоса по языку сообщения,
  маршрутизация кириллица/латиница двумя голосами, чтение таблиц построчно,
  озвучка выбранного сообщения из ленты, мульти-спикерный диалог (Gemini) — заделы
  (docs/roadmap.md).

## Последствия

- Озвучивание работает и полностью офлайн (managed), и на облаках — выбор режима не
  затрагивает остальной код: команда `/tts`, речевой экстрактор, чанкер, точки
  остановки и плеер общие.
- Добавление нового провайдера — это новая реализация `TtsEngine` + вариант
  `TtsMode` + строки каталога настроек; контракт и оркестрация не меняются.
- Формат конфигурации расширяется additive (`#[serde(default)]`) — миграций нет.
