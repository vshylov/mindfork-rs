# i18n Ярус 3 — внешние локали и новые языки без пересборки

> **Статус: РЕАЛИЗОВАНО** (ветка `feat/i18n-external-locales`). Продолжает
> [docs/i18n.md](i18n.md) §5 «Ярус 3». Развилка масштаба подтверждена пользователем
> (2026-07-13): взят **полный** вариант — внешние файлы не только *переопределяют*
> вшитые ru/en, но и позволяют **добавлять новые языки** без пересборки. Оси A (язык
> агента) и B (язык интерфейса) используют один механизм (`shared/i18n`), поэтому
> внешний файл покрывает обе автоматически (в бандле и `prompt.*`/`tool.*`, и `ui.*`).
> **Итог реализации — в конце файла (§7).**

## 1. Цель и рамка

Сегодня бандлы `locales/{ru,en}.json` **вшиты** в бинарь (`include_str!`), а `Lang` —
enum `{Ru, En}`. Ярус 3 даёт:

1. **Override вшитых** — `data/locales/{ru,en}.json` мержится **поверх** вшитого
   по ключам. Частичный файл — норма: переопределяются только присутствующие ключи,
   остальное берётся из вшитого. Позволяет тюнить промпты/чинить en-формулировки без
   пересборки (закрывает отложенное ревью en-формулировок правкой файла).
2. **Новые языки** — `data/locales/<code>.json` с кодом, не совпадающим с вшитым
   (`de`, `fr`, `uk`…), становится первоклассным `Lang`, выбираемым в UI и хранимым в
   `Profile.language`/`config.interface.language`. Недостающие ключи нового языка
   деградируют к референсу (`ru`) на `t()`.

**Вне объёма:** hot-reload (правка файла применяется при перезапуске — прецедент
`&'static`-леака), автоперевод, юнит-покрытие пользовательского содержимого файлов.

## 2. Архитектура

### 2.1 `Lang` — enum + вариант `Ext`

Минимизируем ripple: **сохраняем** варианты `Ru`/`En` (используются как
`Lang::Ru`/`Lang::En` в ~80 местах) и добавляем один вариант для динамических языков.

```rust
#[derive(Debug, Clone, Copy, PartialEq, Eq, Hash)]
pub enum Lang {
    Ru,                    // вшитый референс
    En,                    // вшитый
    Ext(&'static str),     // внешний язык; строка — код (интернирована, Box::leak)
}
impl Default for Lang { fn default() -> Self { Lang::Ru } }
```

- `Copy` сохраняется (`&'static str: Copy`); `Eq`/`Hash` — по содержимому кода
  (`&str` сравнивается по значению, не по указателю → интернирование не обязательно
  для корректности `Eq`, только чтобы получить `&'static` из рантайм-`String`).
- `code(self) -> &'static str`: `Ru→"ru"`, `En→"en"`, `Ext(c)→c`.
- `from_code(&str) -> Lang`: `"ru"→Ru`, `"en"→En`, иначе `Ext(intern(code))`.
- `intern(&str) -> &'static str`: глобальный `LazyLock<Mutex<HashSet<&'static str>>>`;
  новый код → `Box::leak(code.to_string().into_boxed_str())`. Языков конечно —
  ограниченный однократный леак (прецедент — кэш syntect-тем `markdown/code.rs`).

### 2.2 serde — код-строкой

Убираем `#[serde(rename_all="lowercase")]`, пишем ручные `Serialize`/`Deserialize`:
сериализация = `code()`, десериализация = `from_code(&String::deserialize()?)`.
Существующие данные `"ru"`/`"en"` round-trip'ятся байт-в-байт; `#[serde(default)]`
(Default=Ru) не меняется. Профиль с `"language":"de"` десериализуется в `Ext("de")`
даже до регистрации бандла (интернирование не зависит от реестра) → нет опасности
порядка; отсутствующий бандл лишь даёт фолбэк к референсу + предупреждение в лог.

### 2.3 Реестр локалей: вшитые + внешние

```rust
static BUILTIN: LazyLock<HashMap<Lang, &'static Locale>>;   // ru/en, для тестов и базы init
static REGISTRY: OnceLock<HashMap<Lang, &'static Locale>>;  // ставится init() в проде

pub fn init(dir: &Path);              // main.rs, один раз при старте
fn registry() -> &'static HashMap<..> // REGISTRY.get().unwrap_or(&*BUILTIN)
pub fn locale(lang) -> &'static Locale // registry lookup → fallback REFERENCE(ru)
```

- **`init(dir)`**: строит owned-карты вшитых (`ru`/`en`; паника на битом вшитом —
  gate-тест), `overlay_external(dir)` мержит внешние, затем каждую карту один раз
  `Box::leak` в `Locale` → `REGISTRY.set`. Идемпотентно (`set` игнорирует повтор).
- **Без `init` (тесты)**: `registry()` отдаёт `BUILTIN` — чистое вшитое поведение,
  существующие ~1000 тестов не затронуты.
- **`overlay_external(maps, dir)`**: `read_dir(dir)` (нет каталога → no-op, только
  вшитые); для каждого `*.json`:
  - stem = код языка; валидируем `[a-z]+` (иначе `warn` + skip).
  - читаем+парсим **не паникуя** (`parse_external_map -> Result`); ошибка → `warn`
    (в лог, stdout занят TUI) + skip файла (вшитое цело — режим отказа не «промпт
    сломан», а «мягкая деградация»; это и есть отличие внешнего от вшитого).
  - мерж: `maps.entry(lang).or_default()` затем `insert` каждого ключа (override
    per-key). Для вшитого кода — поверх вшитой карты; для нового — поверх пустой
    (недостающие ключи → фолбэк к референсу в `t()`). `info!` о числе ключей.

### 2.4 `Lang::ALL` (вшитые) vs `Lang::all()` (реестр)

- `pub const ALL: &[Lang] = &[Lang::Ru, Lang::En]` — **оставляем**: «вшитые языки».
  Используется гейт-тестами полноты (`key_sets_match`/`placeholder_sets_match`/
  `en_bundle_has_no_cyrillic`) и per-locale структурными тестами — они проверяют
  **вшитые** бандлы (внешние — пользовательский контент, не гейтятся). Нулевой churn.
- `pub fn all() -> Vec<Lang>` — реестр-осведомлённый список (вшитые + найденные
  внешние), детерминированный порядок (`Ru`, `En`, затем `Ext` по коду). В тестах
  (без `init`) = `[Ru, En]`. Используется:
  - **UI-селекторами языка** (ось B `ILanguage`: `spec.rs`/`cycle_lang`; ось A
    `PLanguage`: `apply.rs`/`choice.rs`) — чтобы новые языки были выбираемы;
  - **`present.rs::exit_labels`** — распознавание метки `python.console.exit` по
    **всем** языкам (профиль на `de` пишет её по-немецки → парсер консоли обязан
    её знать).

### 2.5 Метка языка в UI

`Lang::label()`: `Ru→"Русский"`, `En→"English"` (как сейчас, вшитые не трогаем),
`Ext(code) → locale(self).get("ui.lang.name").unwrap_or(code)` — новый язык
самоименуется зарезервированным ключом `ui.lang.name` (иначе показывается его код).

### 2.6 Пути и проводка

- `Paths::locales_dir()` = `root/locales`; каталог создаётся в `Paths::discover`
  (для обнаруживаемости — пустой каталог сигналит «клади файлы сюда»).
- `main.rs`: `i18n::init(paths.locales_dir())` **сразу после** `Paths::discover` +
  `logging::init`, **до** `Storage::open`/загрузки конфига (профиль с `Ext`-кодом
  десериализуется и так, но реестр должен быть готов к первому `locale()`).
- `backup.rs`: каталог `locales/` — пользовательский контент (их override-промпты) →
  **включается** в архив бэкапа (добавить в include-whitelist рядом с `chats/`/
  `dictionaries/`).

## 3. Ripple (точки правки)

| Файл | Правка |
|---|---|
| `shared/i18n.rs` | `Lang` enum+`Ext`, ручной serde, `code`/`from_code`/`intern`, реестр (`BUILTIN`/`REGISTRY`/`init`/`overlay_external`/`parse_external_map`), `all()`, `label()` для `Ext` |
| `shared/paths.rs` | `locales_dir()` + создание каталога в `discover` |
| `main.rs` | `i18n::init(paths.locales_dir())` при старте |
| `features/backup.rs` | `locales/` в include-whitelist |
| `screens/settings/{spec,apply,choice}.rs`, `helpers.rs::cycle_lang` | `Lang::ALL` → `Lang::all()` в 4 UI-селекторах языка |
| `features/tools/present.rs::exit_labels` | `Lang::ALL` → `Lang::all()` |

Гейт-тесты и per-locale структурные тесты (`ALL`) — **не трогаем**.

## 4. Тесты

**Механизм** (tempdir, вшитые не нужны — новые крейты не нужны):
- `overlay_external` мержит override вшитого (частичный `en.json` меняет один ключ,
  остальное — вшитое).
- новый язык (`xx.json`) → `Lang::Ext("xx")` в реестре, присутствующие ключи из
  файла, отсутствующие → фолбэк к `ru`.
- битый JSON внешнего файла → warn+skip, вшитое цело (реестр стандартный).
- невалидное имя файла (`EN.json`/`e n.json`) → skip.
- `all()` включает найденный `Ext`, порядок детерминирован.
- serde `Lang`: round-trip `ru`/`en`/`de`; неизвестный код → `Ext`.
- `Paths::locales_dir` под корнем.

**Изоляция реестра в тестах**: `init` ставит глобальный `OnceLock` — тесты механизма
не должны стрелять по общему реестру. Решение: тестировать **чистые** `overlay_external`/
`parse_external_map`/`from_code`/`all_from(reg)` над локальной картой (аргументом), не
трогая глобальный `REGISTRY`. `init` покрываем одним smoke-тестом идемпотентности
через отдельный процесс-независимый путь (или проверяем составляющие, а не глобал).

Существующие гейты (`key_sets_match`, `placeholder_sets_match`, `en_bundle_has_no_cyrillic`,
`all_ui_keys_referenced_in_code_exist_in_bundle`) — зелёные без изменений.

## 5. Живой прогон

Юнит-тесты покрывают механизм полностью (файловая система — tempdir). Дополнительно
ручная проверка на реальной установке: положить `data/locales/de.json` с несколькими
ключами → в настройках появляется «Deutsch»/«de», выбор языка профиля/UI работает,
недостающие ключи — по-русски, битый файл — предупреждение в логе + приложение живо.
Живой прогон против модели **не требуется** (механизм загрузки, не поведение модели);
регрессия ru/en покрыта существующим юнит-набором.

## 6. Риски

1. **Порядок init vs десериализация.** Снято: `from_code` интернирует независимо от
   реестра; `init` идёт до `Storage::open`. Профиль с неизвестным кодом деградирует к
   референсу, не падает.
2. **Глобальный `OnceLock` в тестах.** Механизм тестируется чистыми функциями над
   локальной картой; глобал не трогаем (см. §4).
3. **Стейл внешнего файла vs новые вшитые ключи.** Per-key overlay: внешний файл
   переопределяет **только свои** ключи, новые вшитые ключи протекают → улучшения
   промптов не теряются. Поэтому **не** копируем шаблоны в `data/locales/` при сборке
   (иначе полная копия молча ревертила бы будущие правки вшитого); документируем
   «клади только переопределяемые ключи».
4. **Неполный новый язык.** Осознанная деградация к `ru` + `info`-лог о покрытии;
   ответственность пользователя (его файл).

## 7. Итог реализации

Реализовано по плану, отклонений от развилок нет.

- **`Lang`** (`shared/i18n.rs`): enum `Ru`/`En`/`Ext(&'static str)` (`Ru`/`En`
  сохранены → нулевой churn на ~80 сайтах), ручной `Serialize`/`Deserialize` код-строкой,
  `code`/`from_code`/`intern` (глобальный `Mutex<HashSet>` + `Box::leak`). `Default`
  через `#[derive(Default)]`+`#[default]` (clippy). `ALL` (вшитые) для гейтов остался;
  добавлен `all()` (реестр-осведомлённый, `all_from(reg)` для теста без глобала).
- **Реестр**: `BUILTIN` (`LazyLock`, тесты/база) + `REGISTRY` (`OnceLock`, ставит
  `init`); `overlay_external` мержит `data/locales/*.json` (валидное имя `[a-z]+`,
  битый/нечитаемый → `warn`+skip, override по ключам / новый язык), `json_to_map`
  (лениентный, `Err` вместо паники), `locale`/`locale_exact` (с/без фолбэка к
  референсу — `label` для `Ext` читает свой бандл без ru-leak). Ключ `ui.lang.name`
  добавлен в оба вшитых бандла (самоименование).
- **Проводка**: `Paths::locales_dir()` + создание каталога в `discover`; `i18n::init`
  в `main.rs` (до `Storage::open`); `locales/` в include-whitelist `backup.rs`;
  4 UI-селектора языка + `present.rs::exit_labels` переведены `Lang::ALL` → `Lang::all()`.
- **Тесты**: 12 новых юнитов в `i18n.rs` (json_to_map, overlay override/новый язык/
  skip битого и плохого имени/нет каталога, sort_langs, code/from_code round-trip,
  serde, label-фолбэк, полный compose над локальной картой) + `Paths::locales_dir`.
  Глобальный `REGISTRY` в тестах не трогается (чистые функции над локальной картой).
  **1015 юнит-тестов зелёные** (+12), clippy `-D warnings`/fmt чисты.
- **Живой прогон** (не против модели — файловый механизм): `data/locales/de.json`
  (3 ключа) при старте реального бинарника → лог `INFO … внешняя локаль: добавлен
  новый язык … lang="de" keys=3`. Интеграция `init`→реестр подтверждена на реальном
  пути; интерактивный выбор языка в TUI — по образцу существующих селекторов (нужен
  живой терминал), покрыт юнит-тестом selector-цикла.
- **Вне объёма (задел)**: hot-reload (правка применяется при перезапуске — прецедент
  `&'static`-леака), автоперевод существующих данных, CLI-экспорт полного бандла.

**Направление i18n (оси A Ярусы 1–3 + ось B) — завершено.**
