## 1. Этап 1 — writer: дефекты потока событий

Ветка `fix/markdown-writer-events`. Только `shared/markdown/writer.rs` (+ тесты).

### 1.1 Лишняя пустая строка перед блочной формулой

**Проблема.** `$$…$$` отдельным абзацем: `start_paragraph` открывает пустую
«текущую» строку (для `push_span`), а `display_math` её не использует — кладёт
контент через `push_line`. Между текстом и формулой два пропуска вместо одного.

**Решение.** В `display_math`: первую строку формулы класть в текущую строку,
если та «пуста по содержимому» (все спаны — whitespace; это сохраняет префиксы
цитат `> `), через `push_span`; иначе — как сейчас, новой строкой. Последующие
строки — `push_line` + `push_span` (а не `Line::from(...)` — чтобы префиксы
цитат добавлялись штатно).

**Тесты:** (a) `текст\n\n$$E=mc^2$$\n\nконец` — между «текст» и формулой ровно
одна пустая строка; (b) формула внутри цитаты — префикс `> ` на строке формулы;
(c) формула первым элементом сообщения; (d) `до $$x$$ после` — прежнее
поведение (формула на своей строке) не сломано.

### 1.2 DisplayMath внутри ячейки таблицы утекает в ленту

**Проблема.** `push_span` перенаправляет в ячейку, а `display_math` зовёт
`push_line` без проверки `in_table_cell()` — строки формулы уезжают в основную
ленту (и рисуются *над* таблицей, т.к. таблица рендерится на `End(Table)`),
ячейка контент теряет.

**Решение.** В начале `display_math`: если `in_table_cell()` — сконвертировать,
склеить строки через `"; "` и отдать одним `push_span`, `return`.

**Тест:** таблица с `$$x+1$$` в ячейке — контент в ячейке, над таблицей ничего.

### 1.3 Автолинк печатает URL дважды

**Проблема.** `<https://example.com>` → `Start(Link)` + `Text(url)` +
`End(Link)`; `end_link` дописывает ` (url)` — «url (url)».

**Решение.** В `start_tag` для `Tag::Link { link_type, dest_url, .. }` не
сохранять `self.link` при `LinkType::Autolink | LinkType::Email` (суффикс не
добавится; `end_link` при `None` уже no-op).

**Тесты:** автолинк — URL один раз; обычная `[t](u)` — прежний вид `t (u)`.

### 1.4 Потеря строк кода при ошибке подсветки

**Проблема.** В `Writer::text` (путь с `code_highlighter`) цепочка
`filter_map(..ok())` молча выбрасывает строку, если `highlight_line`/`into_text`
вернули `Err`. Эталон корректной деградации уже есть — `highlight_code` в
`mod.rs` (ошибка → плоская строка).

**Решение.** Заменить цепочку явным циклом с фолбэком в плоскую строку
(по образцу `highlight_code`); по возможности — общий приватный хелпер
`highlight_or_plain(line, hl) -> Vec<Line>` на оба места.

**Тест:** ошибку syntect искусственно не вызвать — покрытие смоуком «контент
код-блока не теряется» (есть) + юнит на хелпер в плоском пути. Пункт в первую
очередь про устойчивость.

### 1.5 `<br>` трактовать как перенос строки

**Проблема.** `Event::Html`/`InlineHtml` игнорируются целиком. Практический
урон — `<br>` (модели любят его в ячейках таблиц): тег выпадает, слова
склеиваются без пробела.

**Решение.** В `handle_event`: `InlineHtml(s) | Html(s)`, где
`s.trim()` регистронезависимо ∈ {`<br>`, `<br/>`, `<br />`} — вести себя как
`HardBreak` (в ячейке → пробел, иначе → новая строка). Прочий HTML — прежнее
игнорирование (контент между тегами и так приходит отдельными `Text`).

**Тесты:** `a<br>b` в абзаце → две строки; в ячейке таблицы → `a b`.

### 1.6 Инфо-строка метки языка код-блока

**Проблема.** ` ```rust,no_run ` / ` ```python title=x ` — `resolve_syntax`
получает всю инфо-строку и промахивается, блок без подсветки.

**Решение.** В `start_codeblock` резолвить по первому токену
(`lang.split([',', ' ', '\t']).next()`), в строке заборчика печатать исходную
метку (это данные).

**Тест:** ` ```rust,no_run ` даёт RGB-спаны подсветки.

### 1.7 Горизонтальная линия на ширину панели

**Проблема.** `rule()` рисует `───` (3 символа) — на фоне полноширинных таблиц
выглядит обрубком.

**Решение.** `"─".repeat(self.width.max(3))` — ширина панели уже есть у
`Writer` (используется таблицами); строка ≤ ширины, повторный перенос ленты —
no-op. Существующих тестов на `───` нет (проверено), но прогнать тесты
`message_feed` (рейл у DIM-строк).

**Тест:** линия занимает ширину `width`.

### 1.8 Изображения: сохранять URL

**Проблема.** `Tag::Image` не обрабатывается: alt-текст печатается (события
`Text` внутри), URL теряется.

**Решение.** Отдельное поле `image: Option<String>` (не переиспользовать
`self.link` — картинка бывает вложена в ссылку) + `End(Image)` → суффикс
` (url)` стилем ссылки, как у `end_link`.

**Тест:** `![alt](http://x/i.png)` → `alt (http://x/i.png)`.

## 2. Этап 2 — latex: деградация неизвестного + таблицы символов

Ветка `feat/latex-tables`. Только `shared/markdown/latex.rs` (+ `mod.rs` п. 2.7).

### 2.1 Неизвестные brace-команды не склеивать с аргументами

**Проблема.** Финальный срез скобок в `latex_to_unicode` глобальный:
`\overbrace{a+b}` → `\overbracea+b`, `\dfrac{a}{b}` → `\dfracab`. Деградация
нечитаема и хуже, чем оставить как есть.

**Решение.** В `apply_brace_commands`, ветка «имя не распознано, за ним `{`»:
скопировать `\name` и **все подряд идущие группы** с защищёнными скобками
(те же сентинелы `LBRACE`/`RBRACE`, что у литеральных `\{`/`\}` — вынести их в
модульные константы), содержимое групп — рекурсивно. Финальный срез вернёт
`{`/`}` на место: `\foo{a}{b}` остаётся `\foo{a}{b}`, причём `a`/`b` внутри
конвертированы (`\foo{\alpha}` → `\foo{α}`).

### 2.2 Частые команды, которых не хватает

- **`\dfrac`/`\tfrac`/`\cfrac`** — алиасы `\frac` (модели эмитят часто).
- **`\binom{n}{k}`** → `C(n, k)`.
- **`\sqrt[n]{x}`**: распознать опциональный `[n]` после `sqrt`; `3` → `∛(x)`,
  `4` → `∜(x)`, иначе — если `n` целиком мапится в superscript → `ⁿ√(x)`,
  фолбэк `√[n](x)`. Сейчас получается `√ [3](x)`-подобная каша.
- **`\left.` / `\right.`**: после снятия модификатора съедать
  делимитер-точку (сейчас остаётся висячая `.`). В `replace_commands`: если
  подставили `""` для `left`/`right` и следующий символ `.` — пропустить его.
- **`\overset{a}{b}` / `\underset{a}{b}` / `\stackrel{a}{b}`** → базовый
  аргумент `b` (аннотация опускается, как диакритика у акцентов;
  `\overset{def}{=}` → `=`).
- **Текст-обёртки** (`is_text_command`): + `mbox`, `emph`, `textnormal`,
  `texttt`, `textsf`, `textsl`, `textup`, `overrightarrow`, `overleftarrow`,
  `overbrace`, `underbrace`.

### 2.3 Пополнение таблицы символов (`command_symbol`)

Правило отбора: **только BMP**, частота в выводе моделей. Обязательный список:

| Команды | Глиф |

| `lfloor` / `rfloor` / `lceil` / `rceil` | ⌊ ⌋ ⌈ ⌉ |
| `mid` | \| |

| `setminus` / `smallsetminus` | ∖ |
| `cong` / `simeq` | ≅ ≃ |
| `vdash` / `dashv` / `models` / `vDash` | ⊢ ⊣ ⊨ ⊨ |
| `triangleq` / `coloneqq` / `coloneq` | ≜ ≔ |
| `Longleftarrow` / `longleftrightarrow` / `Longleftrightarrow` | ⟸ ⟷ ⟺ (симметрия к уже имеющимся) |
| `hookrightarrow` / `hookleftarrow` / `twoheadrightarrow` / `rightsquigarrow`, `leadsto` | ↪ ↩ ↠ ⇝ |
| `nearrow` / `searrow` / `nwarrow` / `swarrow` | ↗ ↘ ↖ ↙ |
| `vartheta` / `varsigma` / `varrho` / `varkappa` / `varpi` | ϑ ς ϱ ϰ ϖ |

Расширение сверх списка — на усмотрение исполнителя (то же правило BMP).
Тест — выборочно по группам, не на каждый глиф.

### 2.4 `normalize_delimiters`: тильда-заборы и незакрытый backtick

- **`~~~`-заборы**: ряд из ≥3 тильд трактовать как забор (скип до закрывающего
  ряда ≥ той же длины), по аналогии с backtick-рядами. Порог ≥3 не задевает
  `~~зачёркивание~~`. Сейчас `\(…\)` внутри `~~~`-блока конвертируется —
  **порча кода** (RAG-чанкер `~~~` уже учитывает, рендер — нет). Без анкора к
  началу строки (KISS: ряды ≥3 тильд в прозе не встречаются).
- **Незакрытый короткий backtick-ряд (1–2)**: сейчас «съедает» остаток
  сообщения (копия дословно до конца) — одинокий `` ` `` в прозе отключает
  нормализацию формул после себя. По CommonMark незакрытый ряд — литерал:
  скопировать сам ряд и **продолжить** нормализацию. Для рядов ≥3 (заборы)
  оставить прежнее «до конца дословно» — это правильное поведение для
  стриминга (незакрытый ` ``` ` в момент генерации — норма, внутри него
  нормализовать нельзя).

**Тесты:** `\(x\)` внутри `~~~`-блока не тронут; `~~strike~~` не считается
забором; формула после одинокого backtick нормализуется; формула внутри
незакрытого ` ``` ` — нет.

### 2.5 Лимит глубины рекурсии `apply_brace_commands`

Патологическая вставка (тысячи вложенных `\frac`) может переполнить стек —
рекурсия без лимита. Внутренняя функция с параметром `depth`, `MAX_DEPTH ≈ 64`;
глубже — копировать группу дословно. Тест: 10 000 вложенных `\frac{` не паникует.

### 2.6 (попутно) Опечатка в док-комменте

`mod.rs:1` — «lёгкая» (латинская `l`) → «лёгкая».

## 3. Этап 3 — latex: буквенные индексы, `\mathbb`, скобки-фолбэк

Ветка `feat/latex-scripts`. Только `latex.rs`.

### 3.1 Буквенные верхние/нижние индексы

Сейчас `superscript`/`subscript` знают цифры и знаки (+ `n`, `i` сверху), из-за
чего не конвертируются самые частые формы: `x_i`, `a_n`, `x^T`,
`\sum_{i=1}^{n}` (даёт асимметричное `∑_i=1ⁿ`).

Дополнить:

- superscript, строчные: `ᵃᵇᶜᵈᵉᶠᵍʰⁱʲᵏˡᵐⁿᵒᵖʳˢᵗᵘᵛʷˣʸᶻ` (в Unicode нет `q`);
- superscript, заглавные: `ᴬᴮᴰᴱᴳᴴᴵᴶᴷᴸᴹᴺᴼᴾᴿᵀᵁⱽᵂ` (нет C F Q S X Y Z);
- subscript: `ₐₑₕᵢⱼₖₗₘₙₒₚᵣₛₜᵤᵥₓ`;
- (опционально) греческие, где есть: sup `ᵝᵞᵟᶿᵠᵡ`, sub `ᵦᵧᵨᵩᵪ`.

Семантика «всё-или-ничего» на группу сохраняется (`x_b` остаётся `x_b`).

### 3.2 Фолбэк несмапленной группы — круглые скобки

Сейчас при неудаче маппинга `_{i=1}` остаётся `_i=1` (фигурные скобки срезает
глобальный проход — группировка теряется). Новое поведение: группа, которую не
удалось смапить, конвертируется в `_(…)` / `^(…)` (содержимое уже прошло замену
команд). Одиночный символ без группы — как раньше (`x^q` → `x^q`).

### 3.3 `\mathbb{…}` → настоящие double-struck (BMP)

Спец-ветка в `apply_brace_commands` **до** общего `is_text_command`: группа из
одной заглавной с BMP-аналогом → глиф: `ℂ ℍ ℕ ℙ ℚ ℝ ℤ`. Иначе — прежний фолбэк
(содержимое как есть): `\mathbb{XY}` → `XY`. Опционально тем же механизмом
`\mathcal` → `ℬ ℰ ℱ ℋ ℐ ℒ ℳ ℛ` и `\mathfrak` → `ℭ ℌ ℑ ℜ ℨ`.
Supplementary-plane (`𝔸…`, строчные) **не берём** — поддержка терминалами
неровная (см. прошлые грабли suppl-plane во вводе), выигрыш мал.

**Тесты:** `x_i`→`xᵢ`, `a_n`→`aₙ`, `x^T`→`xᵀ`, `\sum_{i=1}^{n}`→`∑ᵢ₌₁ⁿ`,
`x \in \mathbb{R}`→`x ∈ ℝ`, `\mathbb{XY}`→`XY`, фолбэк `x^{q+}`→`x^(q+)`.

## 4. Этап 4 — latex + writer: окружения и режим формулы

Ветка `feat/latex-environments`. `latex.rs` + точки вызова в `writer.rs`.
Самый ценный этап по качеству: `\begin{aligned}…\end{aligned}` — главный
источник «каши» от моделей.

### 4.1 Режим формулы (Inline / Display)

Внутренняя функция получает `MathMode { Inline, Display }`; наружу — два тонких
враппера `latex_to_unicode` (Inline, прежняя сигнатура — тесты этапов 2–3 не
трогаются) и `latex_to_unicode_display`. Вызовы: `InlineMath` → Inline,
`display_math` → Display.

### 4.2 Новый проход `strip_environments`

В пайплайне — после защиты литеральных `\{`/`\}`, до `apply_brace_commands`.
Проход сканирует пары `\` + символ (экранированные `\&`, `\\` и т.п. видит
парой, не по одному):

- `\begin{name}` / `\end{name}` → удалить вместе с группой имени (включая
  `align*` и пр.). Обрамление матриц скобками по типу окружения — **не в MVP**
  (просто снять; записано в §8).
- `\\` (+ опциональный вертикальный отступ `[6pt]` — съесть) → разделитель
  строк: Display → `\n`, Inline → `"; "`.
- одиночный неэкранированный `&` (выравнивание) → удалить; `\&` остаётся.
- `\hline`, `\notag`, `\nonumber` → удалить; `\label{…}`, `\cline{…}` → удалить
  вместе с группой.

### 4.3 Санация Inline-вывода

В Inline-режиме на выходе `\n` → пробел: спаны ratatui не должны содержать
переводов строк (источник — как `\\`, так и переносы внутри `$…$` в исходнике).

### 4.4 `\backslash`

В таблицу команд: `\backslash` → `\` — литеральный бэкслеш в математике теперь
пишется так (семантика `\\` меняется на «разделитель строк», см. §9).

**Тесты:** display `\begin{aligned} x &= y \\ z &= w \end{aligned}` → две
строки `x = y` / `z = w`; `cases`; `pmatrix` (содержимое построчно); inline
`$a \\ b$` → `a; b`; `\label{eq:1}` исчезает; `\\[4pt]`; `\&` сохраняется;
`\backslash` → `\`; `$$`-формула с окружением внутри цитаты (совместно с 1.1).

## 5. Этап 5 — writer: эвристика «диапазон цен — не математика»

Ветка `fix/math-price-guard`. Только обработчик `InlineMath` в `writer.rs`.

**Проблема.** `ENABLE_MATH` глобален: «$5-$10» → `InlineMath("5-")` — доллары
исчезают, «5-10» превращается в «5-» + «10». (Одиночные цены вида «$5 стоит»
pulldown и так не матчит — закрывающему `$` нельзя стоять после пробела.)

**Решение.** Перед конвертацией: если содержимое состоит только из
`[0-9 . , пробел - – /]` **и оканчивается на `-` / `–` / `/`** (сигнатура
диапазона/дроби цен, а не законного числа) — ре-эмит литералом `$…$` текущим
стилем. Законные `$3.14$`, `$2+2$`, `$n$`, `$O(n)$` не затрагиваются
(оканчиваются цифрой/буквой либо содержат math-символы). `DisplayMath` не
трогаем.

**Тесты:** `$5-$10`, `$5/$7` → дословно с долларами; `$3.14$`, `$2+2$`,
`$x^2$` → прежняя конвертация.

## 6. Этап 6 — message_feed: кэш рендера (производительность)

Ветка `perf/feed-render-cache`. Только `widgets/message_feed.rs`.
Независим от этапов 1–5, самый большой системный выигрыш.

**Проблема.** `build_lines` на каждый dirty-кадр заново прогоняет
`markdown::render` (включая syntect) по **всем** сообщениям чата + повторный
`wrap`. Во время стриминга dirty поднимается каждым чанком (с коалесцией тиком
50 мс → до ~20 полных ре-рендеров истории в секунду); каждый шаг колеса — тоже
полный ре-рендер. Меняется же только хвостовое сообщение.

**Дизайн.**

- Поля в `MessageFeed`: `cache: Vec<CachedBlock>` + `cache_key:
  Option<CacheKey>`.
  - `CacheKey { width: usize, palette: Palette, show_thoughts: bool }` —
    `Palette` уже `Copy + Hash + Eq` (ключ кэша syntect-тем). Смена ключа
    (ресайз, тема/компат, `Ctrl+T`) → `cache.clear()`.
  - `CachedBlock { fingerprint: u64, lines: Vec<Line<'static>> }` — **точный
    вклад сообщения** в `build_lines`: тело после markdown, переноса в `inner`,
    рейла и решения о хвостовом разделителе (разделитель — функция самого
    блока, см. `body_ends_blank`).
- `fingerprint` — `std::hash::DefaultHasher` по всем полям `FeedMessage`
  (`role`, `text`, `thoughts`, `streaming`, `tools[]`: name/arguments/result/
  text_offset). Хеш O(len) против рендера O(len·markdown+syntect) — на порядки
  дешевле. Стримящееся сообщение меняет `text` каждым чанком → фингерпринт не
  совпал → пересчитывается только оно. Переактивация чата перестраивает
  `Vec<FeedMessage>`, но фингерпринты прежних сообщений совпадут — кэш
  переживает её бесплатно; `cache.truncate(messages.len())` на случай усечения.
- Отдача из кэша — клон `Vec<Line<'static>>` (MVP: memcpy строк на порядки
  дешевле markdown+syntect). Вариант с заимствованием (`Line<'a>` из
  `Cow::Borrowed` без копий строк) — возможное продолжение, в MVP не идём
  (усложняет сигнатуры).
- Наружный `flat_map(wrap_line)` в `render()` остаётся (страховочный no-op
  проход по уже вписанным строкам — дёшев).
- Плейсхолдер пустой ленты — вне кэша. Коллизия u64-хеша теоретична
  (последствие — устаревший кадр до следующей мутации), принимаем.

**Тесты.**

- **Golden-эквивалентность** — главный: для сценариев (обычный чат;
  стрим-чанки по одному; tool-блоки; мысли свёрнутые/развёрнутые; смена ширины;
  смена палитры; rewrite хвоста) вывод `build_lines` тёплого кэша построчно
  равен выводу свежего `MessageFeed::new()` на тех же данных.
- Мутация текста сообщения инвалидацирует (новый текст появляется в выводе).
- `toggle_thoughts` / смена палитры / ширины дают новый корректный вывод.
- (опционально) счётчик реальных вызовов рендера под `#[cfg(test)]` — что на
  повторном кадре пересчитан только изменённый блок.

## 8. Вне объёма (зафиксированные не-цели)

- **Полный LaTeX / рендер формул в изображение** — как и раньше (spec, ADR 0003).
- **Отступные (4 пробела) код-блоки в `normalize_delimiters`**: распознавание
  требует блочного контекста (продолжения списков тоже с отступом) — риск
  ложных пропусков конверсии выше пользы; `\(` внутри отступного кода остаётся
  известным ограничением (кейс редкий, модели эмитят fenced-блоки).
- **Обрамление матриц по типу окружения** (`pmatrix` → `(…)` и т.п.) — MVP
  просто снимает обёртки; вернуться, если живой вывод покажет потребность.
- **Компат-гейт math-глифов** (WGL4-безопасное подмножество таблицы при
  `terminal_compat`): математика — контент, а не оформление; `⁴…⁹`/стрелки в
  conhost дают тофу уже сейчас. Задел: `render` уже получает `Palette` с
  флагом — при желании протянуть в `latex_to_unicode`.
- **Заимствующий кэш ленты** (без клона строк) — после MVP-кэша, по замерам.
- **Курсив/стиль для math-спанов** — вкусовое, отдельным микро-PR при желании.
- **Горизонтальный скролл широких таблиц** — существующий задел ADR 0003, не
  трогаем.

## 9. Существующие тесты, которые меняются

Смена зафиксированного поведения — осознанная, тесты обновляются в своём этапе:

| Тест (`latex.rs`) | Было | Станет | Этап |
|---|---|---|---|
| `escaped_backslash_and_brace` | `a \\ b` → `a \ b` | `\\` — разделитель строк (Inline: `a ; b`); литеральный бэкслеш — `\backslash` | 4 |
| `unmappable_script_strips_group_braces` | `x^{ab}` → `x^ab` | `ab` теперь мапится (`xᵃᵇ`); пример сменить на немаппимое: `x^{q+}` → `x^(q+)` | 3 |
| `frac_sqrt_and_text_wrappers` | `\mathbb{R}` → `R` | `ℝ` | 3 |

## 10. Порядок и зависимости

```
Этап 1 (writer-дефекты)      — независим, первым (мелкие точечные фиксы)
Этап 2 (latex-таблицы)       — независим
Этап 3 (latex-индексы)       — после 2 (общие места в latex.rs, меньше конфликтов)
Этап 4 (окружения, MathMode) — после 2–3 (меняет пайплайн latex_to_unicode)
Этап 5 (эвристика цен)       — в любой момент (изолированный обработчик InlineMath)
Этап 6 (кэш ленты)           — независим, можно параллельно любым
```

Этапы 2 и 3 при желании сливаются в один PR (оба — локальные правки таблиц
`latex.rs`); 1, 4, 5, 6 — строго отдельными.
