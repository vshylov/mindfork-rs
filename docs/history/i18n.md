# Мультиязычность (i18n): язык агента и язык интерфейса

> **Статус: направление ЗАВЕРШЕНО (Ярусы 1–3 оси A + ось B).** Ярус 1 —
> инфраструктура (`shared/i18n.rs` + бандлы ru/en) + `Profile.language` с замком +
> перевод горячего ядра (промпты фоновых задач, `POLICY_CORE`/протокол, каркас «модели
> себя», дайджест, дефолты). **Ярус 2 — все 35 инструментов** (описания/схемы/
> результаты/ошибки) переведены по группам 2a→2b→2c (см. §5). **Ярус 3 — внешние
> `data/locales/*.json` поверх вшитых + новые языки без пересборки**
> ([docs/history/i18n-external-locales.md](i18n-external-locales.md), §5). **Ось B — язык
> интерфейса** ([docs/history/i18n-ui.md](i18n-ui.md)). Все развилки §4
> подтверждены (решения — по тексту ниже).
> Развилки §4 требовали подтверждения пользователя **до** реализации (AGENTS.md §1).
> Исходная постановка (2026-07-12): «возможность указания языка для профиля агента;
> все служебные промпты — в отдельный json-файл, относящийся к выбранному языку».
> Обновлено решениями пользователя 2026-07-12: язык выбирается при создании профиля
> и **фиксируется** при появлении данных (§3.2); язык профиля **независим** от языка
> UI (§3.2); тесты берут ожидаемые тексты из бандла и гоняются по всем локалям (§3.5).

## 1. Мотивация и рамка

Сегодня **весь** служебный текст приложения — русский: системные промпты фоновых
задач, описания инструментов в схемах, тексты результатов инструментов, каркас
рендера «модели себя», подписи ролей в дайджестах, UI-хром. Пользовательская же
часть — системное сообщение профиля, приветствие, имена ролей — уже редактируется
per-profile.

Проблема проявляется на **профиле с не-русским системным промптом**: модель получает
промпт-салат — англоязычную персону, к которой приложение подмешивает русский
«протокол ведения модели себя», русские описания 30+ инструментов и русские ворота
(«Похожие заметки… перепиши через note_revise»). Следствия: утечки русского в ответы,
худшее следование инструкциям слабых локальных моделей, русские заголовки авто-названия
на английскую переписку каркасом «Пользователь:/Ассистент:».

Ключевое различение, вокруг которого построен весь план — **две независимые оси**:

- **Ось A — язык агента** (тексты, которые читает *модель*): служебные промпты,
  описания/схемы инструментов, результаты инструментов, каркас инъекций. Определяется
  **профилем** (у каждого агента свой язык) — ровно предложение пользователя.
- **Ось B — язык интерфейса** (тексты, которые читает *человек*): статус-бар, экран
  настроек, справка, ошибки, баннеры. Определяется **глобальной настройкой** — один
  на приложение. От языка агентов **независима** (решение пользователя 2026-07-12):
  русский UI и англоязычные агенты — законная комбинация, никакого наследования
  между осями.

Оси пересекаются в одном месте: результаты инструментов и «модель себя» видит и
человек (tool-карточки в ленте, экран `F3`). Принцип: **эти тексты следуют языку
агента** — они в первую очередь для модели, а человек, заведший англоязычного агента,
ожидает английский и в его карточках.

### 2.3 Что НЕ локализуется (осознанно)

- **id инструментов и имена JSON-полей** — wire-протокол (`note_save`, `content`).
- **Тег `@self`**, ключи конфига, имена команд `/rag add|remove|list|rebuild`
  (алиасы — возможный задел, не сейчас).
- **Логи** (`tracing` в файл) и **комментарии/доки** — конвенция «на русском»
  (CLAUDE.md) не меняется.
- **Данные, написанные моделью** (заметки, summary/цели/черты «модели себя», RAG) —
  живут на языке диалога; смена языка профиля их **не переводит** (§6.4).
- **Словари спелл-чека** — уже мультиязычны (en_US/en_GB/ru_RU), ортогональны.
- **Обёртки HTTP-клиентов** (`shared/api/{openai,anthropic,gemini}`) — контексты
  вокруг сетевых ошибок: основное содержимое — тело ошибки сервера / строка ОС
  (непереводимо в принципе), локализация трёх-четырёх слов обвязки не окупает
  протяжку локали во все клиенты (граница, docs/history/i18n-cli.md §7). Предполёт/probe
  managed `llama-server` (`shared/api/managed.rs`), напротив, **локализованы** —
  они всплывают в статус-чипе (`ui.err.managed.*`, i18n CLI этап 3).
- **Пре-language контексты** `shared/paths.rs`/`Paths::resolve` (до определения языка
  CLI — битый `defaults.json`, разрешение exe) — на **английском** (docs/history/i18n-cli.md §7).

## 3. Предлагаемая архитектура

### 3.1 `shared/i18n.rs` — свой микро-модуль, без новых крейтов

По прецеденту `calc.rs`/ADR 0003 (проект избегает крейтов, когда своё решение —
~150 строк): `rust-i18n` — глобальная локаль процесса (не per-profile),
`fluent-rs` — оверкилл (плюрализация/грамматика нужны UI-оси, не промптам) и чужой
DSL. Если ось B потребует честной плюрализации — пересмотреть отдельно.

```rust
// shared/i18n.rs (эскиз)
pub enum Lang { Ru, En }                    // serde lowercase, Default = Ru
pub struct Locale { lang: Lang, map: HashMap<String, String> }
impl Locale {
    pub fn t(&self, key: &str) -> &str;                    // c fallback: ru → сам ключ
    pub fn tf(&self, key: &str, args: &[(&str, &str)]) -> String; // подстановка {name}
}
pub fn locale(lang: Lang) -> &'static Locale;  // LazyLock-таблица вшитых бандлов
```

- Бандлы — `locales/ru.json`, `locales/en.json` в репозитории, `include_str!` +
  разбор при первом обращении (`LazyLock`). Пропущенный ключ **никогда не паникует**:
  fallback на `ru` (референсный язык), затем на сам ключ.
- Плейсхолдеры — именованные `{name}`, простая подстановка (без plural-правил:
  существующие формулировки уже нейтральны к числу — «×{n}», «заметок: {n}»).
- Внешние файлы (`data/locales/*.json`, override/новые языки без пересборки) —
  Ярус 3: грузятся при старте поверх вшитых (`Box::leak` — прецедент кэша
  syntect-тем в `markdown/code.rs`).

**Формат файла — JSON** (конвенция проекта + просьба пользователя). Недостаток JSON
для длинных промптов — `\n`-эскейпы; решается значением-**массивом строк**
(`["строка 1", "строка 2"]` → `join("\n")` при загрузке) — читаемо и остаётся JSON.

### 3.2 Язык профиля: выбирается при создании, фиксируется данными

**Решение пользователя (2026-07-12).** Мотив: «модель себя», модель собеседника,
заметки и прочая память профиля пишутся на одном языке — значит, язык выбирается
**при создании профиля**, а его смена **запрещается**, как только у профиля появились
данные. Ограничение осознанно упрощает реализацию: смешение языков внутри данных
одного профиля становится невозможным по построению.

- `Profile.language: Lang` — **конкретное значение, не `Option`** (`#[serde(default)]`
  → все существующие профили читаются как `Ru`, что верно: их данные русские).
- **Глобального языка агентов нет.** Идея фолбэка `Option<Lang>` → `AppConfig.language`
  из первой версии плана **отвергнута**: язык профиля не привязан к языку UI (ось B,
  будущее). Настройка языка интерфейса появится с осью B и на профили влиять не будет.
- **Выбор при создании**: `Ctrl+N` в настройках создаёт профиль мгновенно (диалога
  нет), поэтому «выбор при создании» реализуется так: новый профиль наследует язык
  профиля, выбранного в настройках в момент создания (fallback `Ru`; bootstrap-профиль
  первого запуска — `Ru`), а поле «Язык» в подсекции Персона **редактируемо, пока у
  профиля нет данных** — выставить его можно первым действием после создания.
- **Замок**: предикат «данные есть» = видимые чаты профиля > 0 **ИЛИ** «модель себя»
  непуста **ИЛИ** активные заметки (включая `@self`) > 0. RAG-документы в предикат
  сознательно не входят: язык файлов базы знаний задаёт пользователь, не агент.
  Двойной гейт: (1) поле в настройках рисуется заблокированным с подсказкой-причиной
  (паттерн «честных гейтов» инструментов, `FieldRow.warn`); снимок
  `AppEvent::Settings` расширяется множеством `language_locked: Vec<Uuid>` (считает
  оркестратор — у экрана нет доступа к чатам/БД); (2) authoritative-проверка при
  `UpdateProfile` в оркестраторе — попытка смены при данных отклоняется с понятной
  ошибкой (страховка от рассинхрона снимка).
- **Следствие**: язык чата = язык его профиля **навсегда** (профиль с чатами язык
  сменить не может) — резолв тривиален, «переключение языка посреди чата» как класс
  сценария не существует. Импортированные (`import-lamellama`) профили получают `Ru`
  через serde-default — корректно для существующих данных.
- **Язык по умолчанию — из `defaults.json`** (не хардкод `Ru`): установочный файл
  рядом с бинарником (`shared::paths::Defaults`) несёт `default_language`, на котором
  создаётся **первый** (bootstrap) профиль и новые профили (`CreateProfile`).
  Инсталлятор заполнит его по выбору языка при установке — тогда первый профиль сразу
  на нужном языке. Резолв: `Paths::default_language()` → `OrchestratorDeps` →
  `Orchestrator::default_language`. См. [docs/install.md §2.1](../install.md).
- **Нюанс bootstrap**: первый профиль создаётся **вместе с дефолтным чатом** → сразу
  залочен на своём языке (сменить язык у него уже нельзя). Поэтому язык выбирается
  установкой (`defaults.json`), а не правкой после. Для агента на **другом** языке,
  чем установочный, создают **новый** профиль (у свежего данных нет → язык
  редактируем) и выставляют язык до первого чата.
- Разлочка честная: скрыл (мягко удалил) все чаты и данные пусты → язык снова
  редактируем — данных, которым он мог бы противоречить, больше нет.

### 3.3 Проводка (какие сигнатуры трогаем)

| Потребитель | Как получает язык |
|---|---|
| Фоновые задачи (title / impersonation / reflection / consolidation) | оркестратор резолвит по профилю чата при спавне, кладёт `&'static Locale` в параметры задачи |
| Agentic-loop и инструменты | `TurnInfo.lang` → `ToolContext.loc` (снимок на ход; `ToolContext::new` — единственная точка правки, SOLID-этап 1) |
| Схемы инструментов | `ToolRegistry::schemas_for(enabled, loc)` → `Tool::schema(loc)` → `description(loc)`/`parameters(loc)` — механическая смена сигнатуры трейта (35 impl); схемы и так строятся на каждый запрос, кэша нет — ничего не ломаем |
| `entities` (рендер «модели себя») | `render_for_prompt`/`render_full`/`age_label` получают `&Locale` параметром (FSD позволяет: `entities → shared`; прецедент ripple — параметр `recent` в narrative-as-notes) |
| Экран `F3` | **не затрагивается**: он рендерит собственные подписи секций («О себе:», «Собеседник», «Наблюдения» в `screens/self_model.rs`), не `render_full` — это UI-хром, ось B; сами данные модели остаются на языке агента |
| `inject_self_model` | +`loc` параметр (чистая функция, тестируема) |

Метаданные каталога для UI (`ui_label()`, `ToolGroup::title()`) — **ось B**, в этом
направлении не трогаются.

### 3.5 Тесты: ожидания из бандла + прогон по всем локалям

**Решение пользователя (2026-07-12).** Ожидаемые служебные тексты в тестах **не
дублируются литералами**, а берутся из того же бандла, что использует код; тесты,
покрывающие локализованные тексты, **прогоняются по всем вшитым локалям** — чтобы
проблемы конкретного языка ловились юнит-набором, а не живым прогоном. (Первая
версия плана предлагала обратное — «ru-бандл байт-в-байт + литералы в тестах ради
нулевого churn»; отвергнуто в пользу per-language покрытия.)

- **Механика — без новых крейтов и без глобального состояния**: локаль и так
  передаётся per-call (`&Locale`), поэтому «прогон по всем файлам перевода» — это
  цикл `for lang in Lang::ALL { … }` внутри теста (фикстуры testkit получают язык
  параметром); сообщение падения включает язык. Отдельная CI-матрица не нужна.
- **Что ловит per-language**: незаполненные/лишние `{плейсхолдеры}`; сломанные
  кросс-ссылки (§6.2) — промпт и генератор блока берут заголовок из одного ключа, и
  согласованность проверяется на каждом языке; влияние **длины перевода** на
  посимвольные бюджеты (`render_for_prompt`: en-текст другой длины — усечение и
  посекционные бюджеты обязаны сходиться на всех локалях); совместимость
  `parse_console` с локализованными метками.
- **Граница выноса**: в бандл уходят ожидания **служебных** текстов; тестовые
  данные-фикстуры (сообщения пользователя «как дела?», имена, содержимое заметок)
  остаются литералами — это данные, не перевод.
- **Нюанс тавтологии**: сравнение «вывод == значение из бандла» не ловит порчу самой
  формулировки (бандл сравнивается сам с собой). Для выстраданных формулировок
  оставляем **смысловые пины** — маленькие per-language таблицы ключевых фраз прямо
  в тестах (ru: «точность важнее угодливости», «СОКРАЩАЙ»; en: их эквиваленты), как
  сегодня `POLICY_CORE.contains("СОКРАЩАЙ")`, но на каждый язык.
- **Gate-тесты полноты** остаются: множества ключей всех вшитых локалей совпадают;
  набор `{плейсхолдеров}` каждого ключа совпадает между языками.
- **Live-смоуки (`#[ignore]`) по локалям не циклуются** (дорого): ru-набор остаётся
  как есть, en-зеркала ключевых сценариев добавляются Ярусами 1–2 с критерием «в
  промпте/результатах нет кириллицы».
- **Внешние файлы локалей** (Ярус 3) юнит-тестами не покрываются (пользовательский
  контент) — при загрузке предупреждение в лог о недостающих ключах + fallback.
- **Цена**: правка сотен ассерт-сайтов на ключи бандла — заметно больший churn, чем
  в первой версии плана; осознанная плата за per-language покрытие. Правка
  механическая, но вдумчивая в местах с плейсхолдерами (ассерт через `tf` с теми же
  аргументами либо по константному фрагменту ключа); идёт погруппно вместе с
  ярусами (тексты яруса → ключи + тесты того же яруса).

## 4. Развилки (подтвердить до реализации)

1. **Объём направления.** (a) Сейчас — только ось A (язык агента: промпты +
   инструменты), ось B (UI) — отдельным направлением позже; (b) обе оси сразу.
   **Решение пользователя (2026-07-12): (a).** Механизм (`shared/i18n`, бандлы)
   проектируется общим — ось B позже переиспользует его через ключи `ui.*`.

2. **Модель распределения языка.** ~~(a) `Option<Lang>` + глобальный дефолт; (b)
   только глобальный~~ — **решение пользователя (2026-07-12), заменяет обе
   альтернативы**: язык выбирается при создании профиля, хранится конкретным
   значением `Profile.language: Lang`, **фиксируется** при появлении данных (чаты /
   «модель себя» / заметки) и **не привязан** к языку UI. Детали и предикат замка —
   §3.2.

3. **Хранение бандлов.** (a) только внешние `data/locales/*.json`; (b) только вшитые
   в бинарь (`include_str!` из `locales/` репозитория); (c) гибрид — вшитые ru+en +
   внешние override/дополнительные языки. **Решение пользователя (2026-07-12): (b)
   для Ярусов 1–2, (c) — Ярусом 3.** Вшитые не имеют режима отказа «файл не
   найден/устарел» (критично: промпты — функциональность, не украшение); внешние
   добавляют бонус — тюнинг служебных промптов пользователем без пересборки, но
   требуют версионирования. Уточнение к исходной постановке: «отдельный json-файл на
   язык» выполняется в обоих вариантах — вопрос лишь в том, читается он из
   репозитория при сборке или с диска при старте.

4. **Описания/схемы инструментов.** (a) локализуются по языку профиля (из бандла);
   (b) один язык для всех — английский (lingua franca LLM, стандарт индустрии).
   **Решение пользователя (2026-07-12): (a)** — сегодняшнее поведение ru-профилей
   (описания, обкатанные живыми смоуками на Gemma) сохраняется байт-в-байт, а
   инфраструктура всё равно строится для результатов инструментов — цена только в
   объёме перевода (~100 ключей).

5. **Стартовый набор языков.** **Решение пользователя (2026-07-12): ru + en.**
   En-перевод делает агент, ревью формулировок — за пользователем (критично для
   «выстраданных» текстов: `POLICY_CORE`, ворота, «точность важнее угодливости»).
   Прочие языки — «ещё один JSON» Ярусом 3.

6. **Язык ответа модели.** **Решение пользователя (2026-07-12): подтверждено как
   принцип.** Язык профиля управляет **только служебным каркасом**; инструкцию
   «отвечай на языке X» приложение **не навязывает** — она живёт в пользовательском
   системном сообщении профиля либо вовсе отсутствует. Мотив: язык ответа не обязан
   совпадать с языком каркаса — например, профиль для изучения иностранного языка
   (каркас на родном, ответы — на изучаемом). `TITLE_SYSTEM_MESSAGE` уже просит
   заголовок «на языке переписки» (а не «на языке профиля») — поведение сохраняется
   в обоих бандлах.

7. **Дефолты новых сущностей.** Новый профиль получает `DEFAULT_SYSTEM_MESSAGE`,
   имя «Ассистент», `CharacterNames` и заголовок «Новый чат» **на языке профиля**
   (снимок — это данные, дальше редактируются как обычно). Существующие
   профили/чаты не трогаются. **Согласовано** решением по развилке 2 (язык
   выбирается при создании — дефолты создаются на нём); нюанс: правка языка до
   первого чата (пока замок открыт) пере-генерирует дефолтные
   `CharacterNames`/системное сообщение, только если пользователь их ещё не менял
   (иначе не трогаем — это уже его данные).

## 6. Риски и подводные камни («сложнее, чем кажется»)

1. **Churn тестов — большой и принятый.** Сотни ассертов на русские подстроки
   переводятся на ключи бандла + цикл по локалям (решение пользователя, §3.5).
   Смягчения: правка идёт погруппно вместе с ярусами (не одним PR-монстром);
   ru-бандл всё равно извлекается из текущих строк **дословно** (поведение
   ru-профилей не меняется, живые смоуки остаются зелёными); смысловые пины ключевых
   фраз защищают формулировки от тавтологии «бандл сравнивается сам с собой».
2. **Кросс-ссылки текстов.** Промпты ссылаются на заголовки блоков, которые
   генерируют другие функции: `reflect_system_message` ↔ «Обзор наблюдений для
   консолидации» (`overview.rs`) и «Поведенческие сигналы» (`behavior_markers`);
   описание `note_link` ↔ «id из note_recall»; `present.rs::parse_console` **парсит**
   вывод `python::format_output` по меткам («код возврата:») — локализация меток без
   правки парсера сломает консольную карточку. Нужен реестр связок + gate-тесты
   внутриязыковой согласованности (§3.5).
3. **Динамические тексты.** Описания `python_exec` (режим/сеть/пакеты) и
   `get/set_sampling` (scope_note по провайдеру) собираются `format!`-ом — в бандле
   это ключи-фрагменты с аргументами, композиция остаётся в коде (как
   `maintenance_protocol()` оборачивает `POLICY_CORE`).
4. **Смешение языков в данных — в основном снято замком.** Смена языка профиля с
   данными запрещена (§3.2), поэтому «русские заметки внутри английского каркаса»
   внутри одного профиля невозможны по построению. Остаточные случаи: (а) Ярус 1 без
   Яруса 2 = en-промпты + ru-инструменты — временное, осознанное состояние; (б)
   пользователь пишет агенту на языке, отличном от языка профиля — каркас останется
   языком профиля (корректно: язык профиля — контракт агента, не автоопределение).
5. **Качество en-перевода промптов.** Формулировки выведены живыми тестами
   (анти-лесть, ворота, «интегрируй и СОКРАЩАЙ») — перевод должен сохранить силу
   нюансов; ревью пользователя + en-смоуки обязательны (развилка 5).
6. **Prefix cache.** Смена языка профиля меняет system → одна пере-обработка
   контекста; операция редкая, принятая цена (прецедент — инъекция «модели себя»,
   решение 2026-07-03).
7. **`&'static Locale` vs внешние файлы.** Вшитые бандлы дают `&'static` бесплатно;
   внешние (Ярус 3) — `Box::leak` при старте (языков конечно, прецедент — кэш
   syntect-тем). Не начинать с `Arc` — не усложнять сигнатуры заранее.
