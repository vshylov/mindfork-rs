[mindfork 0.25.0](https://github.com/vshylov/mindfork-rs/releases) is out. Backups and
restores are three to ten times faster, and pasting a picture into a chat works in more
places and can give the picture a name.

## Backups on every core

A backup used to pack its files one at a time on one core, and the database — most of
a data folder, and most of the wait — in one stream. Now every core packs, the
database is cut into pieces compressed side by side, and it is compacted in memory,
when it fits, instead of through a copy on disk. A restore unpacks on every core too,
and no longer compacts a database the backup already compacted.

On a 4-core machine, with a 352 MB data folder holding a 285 MB database:

- a backup takes **3 seconds** where it took 11;
- a restore over existing data, **4 seconds** where it took 35;
- a restore into an empty folder, under **1 second** where it took 9.

With a password the times are about the same, and the archive is the same zip it was:
older versions and 7-Zip open it, the encrypted one included. *Settings → Data* has
two new rows: *Compression level*, now 6 by default where it was 9 (on real data 9
made no smaller archive and took a fifth longer), and *Threads*, 0 for every core.

**Files in a backup keep their dates.** Every file in an archive was dated
1980-01-01; now each carries its own modification time, and a restore gives the
files their dates back.

## Pictures pasted by name

- **A name that says what the picture shows.** With *Settings → Images → Name pasted
  images* on, the chat's model names a pasted picture by its content:
  `clipboard/sunset-lake.png`, not `clipboard.png`. It is off by default, since it
  sends the picture to the model once more as you paste it — a second of a local
  server, a fraction of a cent in the cloud. `/image paste <name>` names one yourself,
  for free.
- **Each pasted picture its own name.** A picture pasted after one already sent is
  `clipboard-2.png`, so each can be named in `/file list` and handed to the
  assistant's Python.
- **A copied picture file pastes.** Copy a picture in Explorer, Finder or a Linux file
  manager, then `/image paste` (or `Ctrl+V` where the terminal passes it on), and it is
  attached under its own name.
- **The clipboard on Wayland.** On a desktop with no XWayland the app had no clipboard
  at all, and on KDE Plasma, sway and Hyprland a picture copied by a Wayland app could
  not be pasted even with XWayland. The app now talks to the Wayland clipboard
  directly; nothing new needs installing.
- **When there is nothing to paste, it says why**: over SSH, the clipboard read is the
  remote machine's, not the one you copied to; a session with no display, or a
  clipboard that will not open, is named as such.

## Your data

Nothing moves to a new format: the settings and the chats keep their schemas, so going
back to 0.24.0 needs no backup restored. Checked with the published 0.24.0: it reads
and restores a backup this version made, with a password and without, to the same
data; and this version restores 0.24.0's. The new settings take no step: an older
version drops them when it saves its settings.
