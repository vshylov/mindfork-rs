[mindfork 0.28.2](https://github.com/vshylov/mindfork-rs/releases) is out. It is a
small release with two fixes: the dates in a backup, and an updated URL parser.

## The dates in a backup, to the second

Since 0.25.0 every file in a backup carries its modification time, and a restore gives
the file that time back. A zip entry can keep its date in two places:

- **The DOS date-time** in the entry's header, which every zip tool shows. It is local
  time, in steps of two seconds, and it does not say which time zone it was written in.
- **The extended timestamp**, an extra field with the time in UTC, to the second.
  7-Zip, Info-ZIP and mindfork read it first.

mindfork wrote both, but only the DOS date reached the archive. A backup compresses its
files on several threads at once, and each finished entry is copied into the archive as
it is. The [zip](https://crates.io/crates/zip) crate dropped the extended timestamp on
that copy. So a restore dated each file from the DOS field: rounded down to an even
second, and read in the local time of the machine doing the restore. A backup made in
Berlin and restored in New York moved every file by six hours.

We [reported it to the zip crate](https://github.com/zip-rs/zip2/issues/1285), and its
maintainers fixed it. mindfork now uses the fixed version, so every entry keeps its
exact time. That includes the big ones, 16 MiB and up, which mindfork assembles itself
and which now write the field too.

This was checked on a real backup of 628 entries, with a password and without. Every
entry held the exact time, and Python's `zipfile` and Info-ZIP read it. The encrypted
archive was restored with the machine set to New York time, and every file got its
original time back, to the second.

A backup made by 0.25.0–0.28.1 has the DOS date alone. It restores exactly as before.

## A security update

The parser behind the app's network requests is updated to `url` 2.5.9, past
[RUSTSEC-2026-0592](https://rustsec.org/advisories/RUSTSEC-2026-0592.html). Asking a
deeply nested `blob:` URL for its origin could overflow the stack and end the program.
Neither mindfork nor the HTTP client it uses ever asks a URL for its origin, so the app
was not affected.

## Your data

Nothing is migrated: the settings stay at schema 7 and the chats at 9. A backup's
entries carry one more field, the time in UTC. Going back to 0.28.1 needs no backup
restored, and 0.28.1 restores a backup made by this version.
