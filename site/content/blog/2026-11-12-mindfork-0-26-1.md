[mindfork 0.26.1](https://github.com/vshylov/mindfork-rs/releases) is out. It is a
small release with two fixes, both for installing with cargo.

## The data folder, where the other routes keep it

`cargo install mindfork` copies one file, the program, into `~/.cargo/bin`, and until
now the data folder was made beside it: `~/.cargo/bin/data`, among cargo's own
programs. The packages and the Windows installer leave a note beside the program that
puts the data in your user folder, but cargo installs nothing but the program, so no
note could come with it. `cargo uninstall` then took the program away and left the
data folder behind.

A copy cargo installed now knows it: cargo keeps a record of what it installed beside
its `bin/` folder, and mindfork finds itself in it. So a new cargo install keeps its
data where the packages and the installer do:

- `%APPDATA%\mindfork-rs\data` on Windows;
- `~/.local/share/mindfork-rs` on Linux;
- `~/Library/Application Support/mindfork-rs` on a Mac.

`F1` → **About** → *Locations* shows which folder is in use.

## A folder you already have stays

If you installed with cargo before, your chats are in `~/.cargo/bin/data`, and
0.26.1 keeps using that folder as long as it is there. Nothing moves by itself, so an
upgrade never opens an empty app over your conversations. Moving it is one line with
mindfork closed — the commands for each system are on the
[install page](@/install.md#from-crates-io). After the move, the next start finds the
folder in its new place.

## A build without a warning

cargo builds mindfork with the Rust you have installed, not the version the project
tests with. On a Rust newer than 1.96, the build printed one deprecation warning for
mindfork's own code. That line is gone; nothing else changed.

## Your data

Nothing is migrated: the settings stay at schema 7 and the chats at 8. Going back to
0.26.0 needs no backup restored — with one thing to know on a cargo install whose data
is now in your user folder: 0.26.0 looks for it beside the program and would start
empty. A `defaults.json` beside the program holding `{ "mode": "system" }` points
0.26.0 at the same folder. Checked with the published 0.26.0.
