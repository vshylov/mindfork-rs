# mindfork-rs

**Консольное (TUI) приложение ИИ-чата на Rust.** Заточено под **локальные** модели
**Gemma 3/4** и **Qwen 3.5/3.6** (через **llama.cpp `llama-server`**), но через единый
контракт движка поддерживает и **облачные API**: **OpenAI**, **Google Gemini** и
**Anthropic (Claude)** — см. [ADR 0004](docs/decisions/0004-engine-contract-multi-provider.md).
Интерфейс — на [ratatui](https://ratatui.rs). Платформы: **Windows** и **Linux**.
Архитектура — **Feature-Sliced Design (FSD)**.

> Идея проекта — не просто «ещё один клиент к LLM», а попытка сделать локальные
> Gemma/Qwen **осознаннее и интереснее в общении**, дав модели инструменты для
> саморефлексии: читать и менять собственное системное сообщение и параметры
> семплинга, вести заметки о пользователе, поднимать короткоживущего саб-агента
> для «второго мнения». Подробнее — в [spec.md](spec.md) (и в исходном техзадании
> [docs/history/request.md](docs/history/request.md)).

## Возможности

**Чат и интерфейс**
- Полноценный чат-цикл в терминале: **стриминг** ответа, прерывание генерации,
  состояние сервера в статус-баре.
- **Счётчик токенов** в статус-баре (переписка + ответ одним числом): растёт по
  ходу генерации, виден сразу при старте. До ответа сервера переписка показывается
  оценкой (`~`), затем заменяется точным числом из `usage` (`stream_options.
  include_usage`).
- **Список чатов** (`Esc`, полноэкранный): поиск по названию, две сортировки
  (по дате создания / изменения), переименование (`F2`), новый/клон/удаление,
  **авто-название** чата моделью (`Ctrl+R` в окне списка).
- **Копирование переписки в буфер обмена** (`F5`) — и в основном окне (активный
  чат), и в списке чатов (выделенный); кросс-платформенно через `arboard`.
- **Лента сообщений** с собственным рендером **Markdown** (тема, подсветка кода,
  **GFM-таблицы** с умной раскладкой колонок) и **unicode-аппроксимацией LaTeX**
  внутри `$…$`/`\(…\)` (греческие буквы, стрелки, операторы, дроби, корни,
  функции `\log`/`\sin`/…, индексы — без растеризации, дружелюбно к
  JupyterLab-терминалу), сворачиваемым блоком **«мыслей» (CoT)** (`Ctrl+T`) и
  **tool-блоками** (имя/аргументы/результат вызова инструмента).
- Собственный **multiline-ввод** (`Shift+Enter` — перенос, `Enter` — отправка) с
  переносом по словам, точным позиционированием курсора, **быстрой многострочной
  вставкой из буфера** (`Ctrl+V` — переносы сохраняются как текст, не отправляют) и
  **очисткой ввода с отменой** (`Ctrl+K` — удалить весь текст, повтор — вернуть) и
  **попапом выбора эмодзи** (`Ctrl+B` — вставка на месте курсора, помнит последний выбор).
- **Перегенерация** последнего ответа (`Ctrl+R`) и **удаление последнего обмена**
  (`Ctrl+E`, текст пользователя возвращается в поле ввода).
- **Имперсонация** (`Ctrl+U`): модель пишет следующее сообщение **от лица
  пользователя** — потоковый предпросмотр на месте поля ввода, по завершении текст
  вставляется в ввод (`Esc` отменяет). Непустой ввод используется как затравка —
  модель продолжает начатое. Отдельный сервер и семплинг: `shared` (тот же сервер,
  что у ассистента) / `managed` / `external` / облако (`openai` / `gemini` / `claude`).
- **Спелл-чек на лету** для русского и английского (Hunspell): подчёркивание
  ошибок, попап подсказок (`Ctrl+G`), персональный словарь.
- **Темы** auto / dark / light, оверлей помощи по клавишам (`F1` / `?`).
- **Режим совместимости со старым терминалом** (тумблер в настройках, секция
  «Интерфейс»): для conhost Windows 10 и других эмуляторов без поддержки эмодзи —
  безопасные глифы (WGL4/ASCII) вместо эмодзи и редких символов, прямые рамки
  вместо скруглённых, ASCII-спиннер, затемнение фона попапов цветом вместо `DIM`.
- **Прокрутка ленты** колесом мыши или `PageUp`/`PageDown`. Захват мыши —
  **тумблер** (`Ctrl+W`): по умолчанию выключен (работает нативное выделение
  текста мышью), включается под прокрутку колесом (выделение тогда — с `Shift`).
- **Раскладко-независимые** Ctrl-шорткаты (работают и при кириллической раскладке).

**Профили ИИ-собеседника**
- Уникальный id, системное сообщение, опциональное **приветствие** (модель
  начинает разговор первой), имена ролей, набор инструментов, дефолты семплинга.
- **Изоляция заметок и RAG по `profile_id`** — память разных собеседников не
  перемешивается.
- Трёхуровневое разрешение семплинга: `Chat.sampling_override → Profile.default →
  глобальный`.
- **Богатый семплинг** поверх стандартных OpenAI-полей — расширения llama.cpp
  прямо в теле запроса: `min_p`, `top_n_sigma`, `typical_p`, штрафы
  (`repeat_penalty`, DRY, XTC), `mirostat`, `seed`. Для **более живых и
  непредсказуемых** ответов: **динамическая температура** (`dynatemp_range`/
  `_exponent` — температура подстраивается по энтропии на каждом токене),
  **adaptive-p** (`adaptive_target`/`_decay`), **DRY-брейкеры**
  (`dry_sequence_breakers`) и настраиваемый **порядок семплеров** (`samplers`).
  Каждое поле опционально и шлётся только когда задано.

**Инструменты (клиентский agentic-loop)**
- **Интроспекция:** `get/set_sampling`, `get/set_system_message`,
  `get_last_user_message_time` — модель может менять собственное поведение по ходу.
- **Память:** `note_save` / `note_recall`, **RAG** `rag_add` / `rag_search`
  (чанкинг + эмбеддинги + kNN через sqlite-vec). Чанкинг по best practices:
  нарезка по границам предложений/слов с **перекрытием**, мелкие абзацы
  группируются; markdown режется **семантически** (по заголовкам, с защитой блоков
  кода). При поиске соседние чанки **склеиваются** по перекрытию — экономит
  контекст и не путает модель повтором.
- **Загрузка файлов в RAG из поля ввода:** команды `/rag add <путь> [-r]`
  (индексация файла или директории, рекурсивно по флагу; пока `*.txt`/`*.md`) и
  `/rag remove <путь>` (удаление файла/директории из базы). Индексация — фоновая,
  с индикатором прогресса и спиннером; повторное добавление файла **заменяет** его
  чанки (без дубликатов). Командный ввод подсвечивается жёлтым и не проверяется
  орфографией. **`/rag list`** показывает источники базы (счётчик чанков, дата),
  **`/rag rebuild`** реиндексирует базу заново — после смены размеров чанка/
  перекрытия (настраиваются в секции «Инструменты») или embedding-модели с другой
  размерностью. Исходный текст источников хранится в базе, поэтому реиндексация не
  требует исходных файлов на диске.
- **`call_subagent(system_message, message)`** — независимый одно-ходовый запрос
  без истории, инструментов и рекурсии; «второе мнение» под управлением модели.
- **Web-поиск** `web_search` — собственная реализация с мульти-провайдерным
  фоллбэком (DuckDuckGo lite/html → Mojeek → Ecosia) и распознаванием анти-бот
  троттлинга. По умолчанию загружает страницы результатов, извлекает читаемый текст
  и переупорядочивает их по релевантности запросу (эмбеддингами); отключается
  аргументом `fetch_content` или настройкой `config.tools.web_fetch_content`.
- **`fetch_url(url, focus?, summarize?)`** — загрузить страницу и саммаризировать её
  моделью (как `call_subagent`); `focus` фокусирует пересказ, `summarize=false` даёт
  извлечённый текст без модели. Под выключателем web-доступа.
- **`python_exec`** — исполнение Python в отдельном процессе с таймаутом
  (**выключен по умолчанию**, особенно на Windows — нет OS-песочницы).
- **Файлы** `fs_read` / `fs_write` / `fs_list` — чтение/запись/листинг локальных
  файлов (**выключены по умолчанию**, как Python). Опциональная «песочница»
  `fs_root` ограничивает доступ заданным каталогом (выход через `..` блокируется).
- **`calculate(expression)`** — вычислитель математических выражений (свой парсер:
  арифметика, степени, скобки, константы и функции). Без сети/диска.
- **`current_time(format?)`** — текущие дата/время (локальная зона + UTC; `format` —
  строка `strftime`). Без сети/диска.
- **Управление структурой ответа** (опциональны, по умолчанию выключены):
  **`send_followup_message`** — ассистент дописывает текущее сообщение, вызывает
  инструмент и пишет **вторую реплику** отдельным пузырём сразу за первой;
  **`rewrite_current_message`** — если по ходу понял, что ответил неверно, отбрасывает
  начатый ответ и пишет заново (отброшенное сохраняется для ручного восстановления).
  Включаются тумблерами в настройках профиля. Проверены на живых Gemma 4 и Qwen 3.6.
- **Глобальные выключатели**: эффективный набор = `профиль ∩ глобально включённые`
  (web гейтит `web_search`+`fetch_url`, Python — `python_exec`, доступ к файлам —
  `fs_*`); `calculate`/`current_time` безопасны и доступны всегда.

**Прочее**
- **Экран настроек** (`Ctrl+P`): модель/сервер, инференс, семплинг, профили,
  инструменты, интерфейс. Секции «Модель/сервер», «Семплинг» и «Профили» имеют
  подсекции **«Ассистент»/«Имперсонация»**. Смена модели **перезапускает**
  managed-сервер на лету. У managed-сервера настраиваются **FlashAttention**
  (`--flash-attn`) и **спекулятивное декодирование** (`--spec-type`, включая
  `draft-mtp` для MTP-моделей — даёт кратный прирост скорости).
- **Импорт** из LameLLaMA (.NET): `mindfork import-lamellama <dir>` (идемпотентно,
  проверено на 6 профилях / 226 чатах).
- **Резервное копирование/восстановление**: `mindfork backup [-o FILE] [-c 0..9]` и
  `mindfork restore <archive>` (zip с настраиваемым сжатием; восстановление
  транзакционно — pre-restore копия прежних данных и откат при сбое).
- **Портативность и режим хранения**: по умолчанию все данные лежат в подкаталоге
  `data/` рядом с бинарником (папка/флешка самодостаточна); маркер `location.json`
  может перенести их в стандартную ОС-папку или произвольный каталог. Атомарная
  запись + `.bak`, мягкое удаление с каскадом.

## Архитектура

Движок инференса спрятан за трейтом **`EngineBackend`** (`shared/api/contract`), и
приложение — это HTTP-клиент к нему; встраивание модели (rlib с candle/CUDA)
сознательно **не используется**. Поддерживаются несколько провайдеров за одним
контрактом ([ADR 0004](docs/decisions/0004-engine-contract-multi-provider.md)):
- **локальный OpenAI-совместимый сервер** — managed `llama-server` (приложение само
  запускает процесс) или любой external (vLLM / LM Studio / Ollama), `OpenAiClient`
  (Chat Completions, сэмплинг шлётся как есть);
- **облако OpenAI** — `ResponsesClient` (Responses API `/v1/responses`, Bearer-ключ):
  резюме рассуждений («мысли»), `reasoning.effort`, `text.verbosity`; рассуждение
  переотправляется вместе с вызовом инструмента (reasoning-элемент);
- **облако Google Gemini** — нативный `GeminiClient` (`generateContent`,
  `x-goog-api-key`): резюме «мыслей» (`thinkingConfig.includeThoughts`), глубина
  `thinkingLevel` (3.x) / `thinkingBudget` (2.5), `top_k`; подпись мысли
  (`thoughtSignature`) переотправляется на вызове инструмента (обязательна для
  Gemini 3);
- **облако Anthropic (Claude)** — `AnthropicClient` (Messages API `/v1/messages`,
  `x-api-key`) с **extended thinking (CoT)**: adaptive thinking + видимые «мысли»,
  корректные и при вызове инструментов (переотправка thinking-блока с подписью в
  том же ходе).

Выбор провайдера — в настройках единым селектором режима (`managed` / `external` /
`openai` / `gemini` / `claude`); API-ключ задаётся **именем env-переменной** (сам
секрет на диск не пишется). Слои выше `EngineBackend` (оркестратор, agentic-loop,
инструменты, UI) от провайдера не зависят.

Конфигурация движка **вложенная**: у каждого режима/провайдера своя под-секция
настроек (`managed` / `external` / `openai` / `gemini` / `claude`), так что можно
держать настроенными сразу несколько и **переключаться, ничего не теряя**. Экран
настроек показывает только поля выбранного режима, а в облаке скрывает параметры
сэмплинга, которые провайдер не принимает (их значения сохраняются для локальных
моделей). Это касается и движка ассистента, и сервера имперсонации, и эмбеддингов.

> **Почему не xinfer.** Изначально проект проектировался под лёгкую библиотеку
> `xinfer`, но она оказалась сырой по Gemma 4 (бессвязный вывод, плохо собирается
> под Windows). Рабочий бэкенд — **llama.cpp `llama-server`** (OpenAI-протокол,
> `--jinja`). Запуск и протокол — в [docs/install.md §3](docs/install.md).

Ключевые решения:
- **Agentic-loop клиентский** (в оркестраторе): стрим → tool-calls → исполнение →
  новый запрос, до `max_tool_rounds`. Инструменты возвращают результат + эффекты;
  оркестратор — единственный владелец `Chat` — применяет эффекты без локов.
- **Однонаправленный поток UI↔оркестратор**: команды `AppCommand` вверх, события
  `AppEvent` вниз; `generation_id` отбрасывает устаревшие чанки; автомат
  `Idle / Generating / Cancelling`.
- **EOS** по token-id на сервере (поле `stop` не отправляется — анти-самообрыв);
  «мысли» из `delta.reasoning_content` с фолбэком на парсинг `<think>` (llama.cpp),
  у Claude — `thinking_delta` + подпись, у OpenAI Responses — `reasoning.summary` +
  reasoning-элемент, у Gemini — части `thought:true` + `thoughtSignature` на вызове
  (всё для корректного round-trip при tool-use).
- **Хранение**: JSON (конфиг/профили/чаты) + SQLite/sqlite-vec (заметки/RAG),
  изоляция по `profile_id`, мягкое удаление везде.
- **Эмбеддинги** — выделенный embedding-сервер ([ADR 0002](docs/decisions/0002-embeddings-dedicated-server.md)).

### Структура (FSD, зависимости строго вниз)

`app → screens → widgets → features → entities → shared`

| Слой | Содержимое |
|---|---|
| `src/app/` | оркестратор, события, TUI-петля, супервайзер серверов, мост tokio↔UI |
| `src/screens/` | экраны: `chat`, `settings` (отдают `*Intent`, не знают про `app`) |
| `src/widgets/` | `message_feed`, `input_box`, `chat_list`, `profile_list`, `status_bar` |
| `src/features/` | `tools/*`, `spellcheck/*`, `profiles`, `chat_search_sort`, `rename_chat`, `migration` |
| `src/entities/` | доменные типы: `chat`, `message`, `profile`, `note`, `rag`, `sampling` |
| `src/shared/` | `api` (`contract` + реализации `openai` (Chat Completions + `responses/`), `gemini`, `anthropic`, `managed` за трейтом `EngineBackend`), `storage`, `config`, `paths`, `theme`, `markdown`, `wrap`, `keys`, `logging`, … |

UI-крейты выбраны под ratatui 0.30 ([ADR 0001](docs/decisions/0001-ui-crates-ratatui-030.md)):
`tui-scrollview`, ввод — **собственный виджет** (даёт полный контроль над
`Shift+Enter` vs `Enter`, скроллом и подчёркиванием спелл-чека). Markdown —
**собственный рендерер** на `pulldown-cmark` (таблицы + delimiter-LaTeX + тема,
[ADR 0003](docs/decisions/0003-own-markdown-renderer.md)).

## Сборка и запуск

Нужен **Rust** (edition 2024, свежий стабильный toolchain).

```bash
cargo build --release          # бинарник в target/release/
cargo run                      # dev-запуск (нужен НАСТОЯЩИЙ терминал)
```

> TUI требует настоящий TTY. В headless-окружении приложение «висит» — это нормально.

### Подключение модели (llama.cpp)

Пример external-режима — поднимаем `llama-server` вручную и указываем URL:

```bash
# терминал 1: сервер инференса (--jinja обязателен для формата Gemma и tool-calling)
llama-server -m google_gemma-4-E4B-it-Q4_1.gguf \
  --host 0.0.0.0 --port 8000 -ngl 99 -c 8192 --jinja
```

```powershell
# терминал 2 (PowerShell): указываем приложению, куда подключаться
$env:MINDFORK_ENGINE_URL = "http://127.0.0.1:8000/v1"
cargo run
```

В **managed-режиме** приложение само запускает `llama-server` (путь к бинарнику +
GGUF задаются на экране настроек `Ctrl+P` или через env):

```powershell
$env:MINDFORK_LLAMA_BIN = "C:\path\to\llama-server.exe"
$env:MINDFORK_MODEL     = "C:\GGUF\google_gemma-4-E4B-it-Q4_1.gguf"
$env:MINDFORK_NGL       = "99"     # GPU-слои (опц.)
$env:MINDFORK_CTX       = "8192"   # контекст (опц.)
$env:MINDFORK_PORT      = "8000"   # опц.
```

Если в managed-режиме файл GGUF не найден или недоступен, приложение **сразу**
показывает понятную ошибку в статус-баре (а не висит в «сервер: подключение…» до
таймаута загрузки) — наличие модели проверяется ещё до запуска `llama-server`.

В managed-режиме на экране настроек доступны **FlashAttention** (`--flash-attn`:
`auto`/`on`/`off`) и **спекулятивное декодирование** (`--spec-type`) — оно ускоряет
генерацию «черновиком» наперёд. Типы `draft-*` требуют отдельную черновую модель
(`-md` + `-ngld`/`--spec-draft-n-max`/`-n-min`); для **MTP-моделей** (например
`mtp-gemma-4-12B-it.gguf` как черновая к обычной `gemma-4-12B-it`) — `draft-mtp`;
`ngram-*` отдельной модели не требуют. Черновые поля в UI видны только для `draft-*`.

Эмбеддинги для RAG — **выделенный** сервер: `MINDFORK_EMBED_URL` (external) либо
`MINDFORK_EMBED_BIN` / `_MODEL` / `_PORT` (managed). Не настроен → RAG отдаёт
понятную ошибку, остальное работает.

Полные инструкции (режимы, словари, импорт, пути данных) — в
**[docs/install.md](docs/install.md)**.

### Словари спелл-чека

Hunspell-пары `*.aff` + `*.dic` (`en_US`, `en_GB`, `ru_RU`) кладутся в
`dictionaries/` в корне проекта; `build.rs` копирует их рядом с бинарником при
сборке. Нет каталога → спелл-чек просто выключен (не падает). Сами словари **не
входят в репозиторий** (`.gitignore`).

## Горячие клавиши

| Клавиша | Действие |
|---|---|
| `Enter` / `Shift+Enter` | отправить / перенос строки (`Alt+Enter` — тот же перенос на терминалах без kitty-протокола) |
| `Shift+←/→/↑/↓`, `Ctrl+A` | выделить текст / выделить всё |
| `Ctrl+C` / `Ctrl+X` / `Ctrl+V` | копировать / вырезать выделение · вставить из буфера |
| `Esc` | список чатов (открыть/закрыть) · отмена генерации |
| `Ctrl+Q` / `F10` | выход (в т.ч. из списка чатов) |
| `F1` / `?` | справка по клавишам |
| `Ctrl+P` | экран настроек |
| списка чатов (`Esc`) | поиск, сортировки, `F2`/`Ctrl+N`/`Ctrl+D`/`Del`, `Ctrl+R` авто-название, `F5` копировать |
| `F5` | копировать переписку чата в буфер обмена (активный / выделенный в списке) |
| `Ctrl+N` | новый чат (с выбором профиля) |
| `Ctrl+R` | перегенерировать последний ответ |
| `Ctrl+E` | удалить последний обмен (текст → в поле ввода) |
| `Ctrl+U` | написать сообщение от имени пользователя (имперсонация) |
| `Ctrl+K` | удалить весь текст ввода (возврат — `Ctrl+Z`) |
| `Ctrl+Z` / `Ctrl+Y` | отмена / повтор правки поля ввода |
| `Ctrl+T` | свернуть/развернуть «мысли» |
| `Ctrl+G` | подсказки спелл-чека |
| `Ctrl+B` | попап выбора эмодзи (вставка на месте курсора) |
| `Ctrl+W` | тумблер: колесо мыши ↔ выделение текста |
| клик / драг мышью в поле | курсор / выделение текста (при захвате `Ctrl+W`) |
| `PageUp` / `PageDown` / колесо мыши | прокрутка ленты |
| `/rag add <путь> [-r]` | индексировать файл/директорию в RAG (команда в поле ввода) |
| `/rag remove <путь>` | удалить файл/директорию из RAG (команда в поле ввода) |

Ctrl-шорткаты раскладко-независимы (работают при русской раскладке).

> **Колесо мыши и выделение текста делят один механизм терминала** (mouse
> reporting), поэтому захват сделан тумблером `Ctrl+W`. Выкл (по умолчанию):
> мышь выделяет текст как обычно. Вкл: колесо прокручивает ленту, а выделить
> текст можно с зажатым `Shift` (Windows Terminal и большинство терминалов).
> Текущий режим показан в статус-баре.

## Разработка

```bash
cargo test                                 # юнит-тесты (без сервера; 729 зелёных)
cargo clippy --all-targets -- -D warnings
cargo fmt --check
```

Смоук-тесты против живой модели помечены `#[ignore]` и запускаются вручную (без
нужной env-переменной тихо пропускаются):

```powershell
$env:MINDFORK_ENGINE_URL = "http://127.0.0.1:8000/v1"   # чат-сервер (URL включает /v1)
$env:MINDFORK_EMBED_URL  = "http://127.0.0.1:8001/v1"   # эмбеддер (память/RAG-смоуки)
cargo test -- --ignored --nocapture --test-threads=1
```

Покрывают стриминг/финиш, анти-самообрыв на тексте EOS (`<|im_end|>` Qwen и
`<end_of_turn>` Gemma), tool-calling, «мысли», расширения семплинга и control-
инструменты, а также end-to-end модели себя/заметок/нарратива (ворота, граф,
рефлексия, консолидация, кросс-органные связи). **25 `#[ignore]`-смоуков прогнаны
зелёными на Gemma 4 31B + bge-m3** (`llama-server`, ~370с).

**Конвенции:** Rust edition 2024; `anyhow` в прикладных слоях, `thiserror` в
библиотечных `shared`; логи только в файл (`logs/`, stdout занят TUI); тесты рядом
с кодом (`#[cfg(test)]`); комментарии и документация — на русском. Зависимости —
строго вниз по слоям FSD. Перед коммитом: `cargo fmt`, `cargo clippy`, `cargo test`
— всё зелёное.

## Статус

Реализован весь план **M0–M9** плюс обширный пост-M9. Чат-цикл, профили с изоляцией,
инструменты с клиентским agentic-loop, саб-агент, web-поиск и Python под
выключателями, экран настроек, импорт из LameLLaMA, темы, спелл-чек на лету, загрузка
файлов в RAG командами `/rag add|remove` (умный чанкинг с перекрытием + семантический
markdown + склейка при извлечении), **имперсонация** пользователя (`Ctrl+U`, shared/
managed/external), **«модель себя»/собеседника** (`F3`) и **связность заметок**
(семантический recall, граф связей, замещение со «шрамом», авто-«сон», нарратив как
заметки). **Мульти-провайдерный инференс** ([ADR 0004](docs/decisions/0004-engine-contract-multi-provider.md)):
локальный llama.cpp + облако **OpenAI (Responses API) / Google Gemini (нативный
`generateContent`) / Anthropic (Claude)** за единым контрактом, каждый с резюме
рассуждений/«мыслей» и корректным round-trip при tool-use. **853 юнит-теста** зелёные;
`#[ignore]`-смоуки прогнаны на живой связке **Gemma 4 31B + bge-m3** (`llama-server`),
**Claude 4.x** — на живом Anthropic API, **Gemini 3.1 Pro** — на живом Gemini API по
ключу.
